## 陣列上的掃描技巧：雙指標、滑動視窗、前綴和 · 第 3 步

### 概念：Prefix Sum（前綴和）

先把陣列每個位置「之前」的累加總和算好存進一個新陣列 `pre`（長度是原陣列長度 +1，`pre[0] = 0`），之後要查詢原陣列從 `left` 到 `right` 這一段的總和，只要算：

```
sumRange(left, right) = pre[right + 1] - pre[left]
```

因為 `pre[right+1]` 是「加到 right 為止」的總和，`pre[left]` 是「加到 left 之前」多算進去的那一段，兩者相減剛好只留下 `left` 到 `right` 這一段。

跟前兩天學的雙指標、滑動視窗比，那兩者是「邊掃邊算」；前綴和是「先算好存起來，之後直接查表」。特別適合「陣列建好後不太會再變動、但要被重複問很多次區間和」的情境。

⚠ 最容易搞錯：前綴和陣列要開原陣列長度 +1，且 `pre[0]` 必須是 0；少留這一格或忘記歸零，查詢左端點是 index 0 時就會默默算錯。

### 建構與查詢範例

```java
int n = nums.length;
int[] pre = new int[n + 1];
for (int i = 0; i < n; i++) {
    pre[i+1] = pre[i] + nums[i];
}
// 查詢一段區間的和
int sum = pre[r+1] - pre[l];
```

### 這東西用在哪

- **對工程師**：資料建好後不常變動、但要被重複問區間和／平均時，先建前綴和表，查詢就是 O(1)；別每次都重新加總一次。
- **對產品端**：報表功能不管選的日期區間多長都秒開，背後多半是前綴和；反之區間越長轉越久，代表工程師每次都重新加總，資料一多就會變慢。

### LeetCode 練習

[#303 Range Sum Query - Immutable](https://leetcode.com/problems/range-sum-query-immutable/)（Easy）

給一個不會再變動的陣列，設計資料結構支援多次區間和查詢。

```java
class NumArray {
    private int[] pre;

    public NumArray(int[] nums) {
        int n = nums.length;
        pre = new int[n + 1];
        for (int i = 0; i < n; i++) {
            pre[i+1] = pre[i] + nums[i];
        }
    }

    public int sumRange(int l, int r) {
        return pre[r+1] - pre[l];
    }
}
```

複雜度：建構 O(n)（掃一次陣列建前綴和），查詢 O(1)（兩個元素相減）；空間 O(n)（多開一個長度 n+1 的陣列）。

### 術語表

- **Prefix Sum（前綴和）**：陣列裡某個位置之前所有元素的累加總和。
- **Range Query（區間查詢）**：問某個區間的總和、最大值等問題。
- **Precompute（預處理）**：回答問題前先把之後會用到的資料算好存起來。
- **Immutable（不可變）**：資料建好後不會再被修改，前綴和最適合這種情境。
