## 空間複雜度：記憶體也要算，遞迴呼叫堆疊的隱藏成本 · 第 1 步

### 今日概念：Space Complexity — 算的是「額外多用的記憶體」

昨天學了時間複雜度（跑多久），今天學空間複雜度（space complexity）：演算法執行時，除了輸入資料本身，還額外占用多少記憶體，一樣用 Big-O 表示。

![演算法執行時的記憶體空間分類](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_computational_complexity/space_complexity.assets/space_types.png)
圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

一個程式用到的記憶體可分三塊：輸入空間（傳進來的參數本身）、暫存空間（auxiliary space，程式為了算答案額外開的變數/陣列/物件）、輸出空間（回傳結果）。空間複雜度只算「暫存空間」這一塊，不算輸入本身。

- **O(1)（常數空間）**：原地（in-place）操作，多用的空間跟輸入大小無關，永遠固定。
- **O(n)（線性空間）**：另外複製一份跟輸入等大的容器。

```java
// O(n) 空間：另外複製一份
int[] doubleValuesCopy(int[] nums) {
    int[] result = new int[nums.length];
    for (int i = 0; i < nums.length; i++) {
        result[i] = nums[i] * 2;
    }
    return result;
}

// O(1) 空間：原地修改
void doubleValuesInPlace(int[] nums) {
    for (int i = 0; i < nums.length; i++) {
        nums[i] = nums[i] * 2;
    }
}
```

### 這東西用在哪

- **工程師**：資料轉換/批次處理時，能原地改就別多開容器，省記憶體也省 GC；但如果呼叫端還需要保留原資料，貿然原地修改會造成資料被覆蓋的 bug。
- **產品端**：工程師說「這個功能要另外開一份資料複本」，代表記憶體用量會隨資料量等比例成長，資料量小時感覺不到，長到十萬、百萬筆時可能拖慢甚至讓伺服器記憶體不足；也解釋了為什麼有些看似簡單的功能改寫成本比想像中高。

### LeetCode #26 Remove Duplicates from Sorted Array (Easy)

<https://leetcode.com/problems/remove-duplicates-from-sorted-array/>

已排序陣列去除重複，且要求原地（O(1) 額外空間）完成，用雙指標（two pointers）：slow 指向目前不重複區段的最後一格，fast 往前掃描，遇到新數字就讓 slow 前進並覆寫。

複雜度：時間 O(n)（掃一次陣列）；空間 O(1)（只多用 slow、fast 兩個變數）。

```java
class Solution {
    public int removeDuplicates(int[] nums) {
        if (nums.length == 0) return 0;
        int slow = 0;
        for (int fast = 1; fast < nums.length; fast++) {
            if (nums[fast] != nums[slow]) {
                slow++;
                nums[slow] = nums[fast];
            }
        }
        return slow + 1;
    }
}
```

### 今日術語表

| 術語 | 定義 |
|---|---|
| Space Complexity 空間複雜度 | 衡量演算法額外需要多少記憶體，隨輸入大小的變化趨勢 |
| Auxiliary Space 暫存空間 | 程式為算出答案額外開的變數/陣列/物件所占記憶體 |
| In-place Algorithm 原地演算法 | 直接在原資料上修改，不複製等大新容器，暫存空間通常 O(1) |
| Two Pointers 雙指標 | 用兩個游標在同一份資料上移動比較，常用於把 O(n) 空間解法改成 O(1) |
