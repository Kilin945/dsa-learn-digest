## 雜湊函式與負載因子：hashCode、擴容與 rehash · 第 2 步

### Load Factor, Resize & Rehash

![雜湊衝突的最佳情況與最差情況](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_algorithm.assets/hash_collision_best_worst_condition.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

鏈式位址雜湊表在最佳情況下，鍵值對均勻分佈在各個桶中，查詢最快；最差情況下所有鍵值對都在同一個桶，退化成 O(n)。開放定址與鏈式位址只能保證衝突時正常工作，無法減少衝突發生，所以需要負載因子與擴容來控制衝突量。

**負載因子**：load factor = 元素個數 ÷ 桶數。鏈式位址下，平均串長約等於負載因子，查詢約 O(1 + 負載因子)。

**擴容**：超過門檻就換更大的桶陣列。Java HashMap 預設 16 個桶、負載因子 0.75，超過 12 個元素時翻倍成 32。

**Rehash**：桶編號 = hash % 桶數，桶數變了就要重算。例如 hash = 20，16 桶時在 4 號桶，32 桶時在 20 號桶。

```java
int cap = 16;
int hash = 20;
// 擴容前：桶編號 = 20 % 16 = 4
int before = hash % cap;
cap = cap * 2;
// 擴容後：桶編號 = 20 % 32 = 20
int after = hash % cap;
```

**成本**：單次擴容 O(n)，但每次翻倍，總搬移量約 2N，攤還後每次 put 仍是 O(1)。

> ⚠ 擴容不是把陣列拉長就好，每個 key 的桶編號都可能改變，必須 rehash。

### 這東西用在哪

- 寫程式：事先知道筆數就預設初始容量（約 筆數 ÷ 0.75），省掉中途擴容；負載因子是時間與記憶體的取捨。
- 產品端：平常順、偶爾卡一下且越來越稀疏，可能是擴容；桶數約為資料筆數的 1.3 到 2.7 倍，記憶體比資料本身多是用空間換速度。

### 動手寫 · LeetCode

[#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

鏈式位址加擴容：put 後若 size 超過桶數 × 0.75 就翻倍並 rehash。時間平均 O(1)（攤還），空間 O(n)。

```java
class MyHashMap {
  static class Node {
    int k, v;
    Node next;
    Node(int k, int v, Node next) {
      this.k = k;
      this.v = v;
      this.next = next;
    }
  }

  Node[] tab = new Node[16];
  int size = 0;

  public void put(int key, int value) {
    int i = key % tab.length;
    Node head = tab[i];
    Node n = head;
    while (n != null) {
      if (n.k == key) {
        n.v = value;
        return;
      }
      n = n.next;
    }
    // 沒找到：頭插法放進這個桶
    tab[i] = new Node(key, value, head);
    size++;
    // 負載因子超過 0.75 就擴容
    if (size > tab.length * 3 / 4) {
      resize();
    }
  }

  void resize() {
    Node[] old = tab;
    tab = new Node[old.length * 2];
    for (Node h : old) {
      while (h != null) {
        Node next = h.next;
        // 用新桶數重新算桶編號（rehash）
        int i = h.k % tab.length;
        h.next = tab[i];
        tab[i] = h;
        h = next;
      }
    }
  }

  public int get(int key) {
    Node n = tab[key % tab.length];
    while (n != null) {
      if (n.k == key) return n.v;
      n = n.next;
    }
    return -1;
  }

  public void remove(int key) {
    int i = key % tab.length;
    Node n = tab[i], prev = null;
    while (n != null) {
      if (n.k == key) {
        if (prev == null) {
          tab[i] = n.next;
        } else {
          prev.next = n.next;
        }
        size--;
        return;
      }
      prev = n;
      n = n.next;
    }
  }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Load factor | 負載因子 | 元素個數 ÷ 桶數，代表桶有多滿 |
| Bucket | 桶 | 雜湊表裡放資料的格子 |
| Chaining | 鏈式位址 | 同一個桶後面接一串資料 |
| Open addressing | 開放定址 | 衝突時往後找下一個空桶 |
| Threshold | 門檻 | 觸發擴容的元素個數 = 桶數 × 負載因子上限 |
| Resize | 擴容 | 換成更大的桶陣列，Java 每次翻倍 |
| Rehash | 重新雜湊 | 擴容後用新桶數重算每個 key 的桶編號 |
| Amortized | 攤還 | 把偶爾很貴的操作成本平均分攤到每次操作 |
