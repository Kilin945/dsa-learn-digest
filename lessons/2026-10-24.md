## 雜湊函式與負載因子：hashCode、擴容與 rehash · 第 4 步

### Power-of-Two Table Size & Hash Spreading

![雜湊衝突的最佳情況與最差情況](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_algorithm.assets/hash_collision_best_worst_condition.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

開放定址與鏈式位址只負責衝突發生後怎麼收拾，無法減少衝突發生。圖中對照最佳情況（鍵值對均勻分佈在各個桶）與最差情況（全部進同一個桶，退化成 O(n)）。今天要學的是怎麼讓桶編號不被推向最差情況。

**桶編號不是用 % 算的**：Java HashMap 的桶數永遠是 2 的次方，所以 `hash % n` 改寫成 `(n - 1) & hash`。n = 16 時 n - 1 = 1111（二進位），AND 之後只留最低 4 個位元。

**副作用：高位元被丟掉**：n = 16 只看最低 4 位元，65536、131072、196608 的低 16 位元全是 0，全進 0 號桶。

**解法：擾動（spread）**：`h ^ (h >>> 16)` 把高 16 位元混進低 16 位元，上例會分別落進 1、2、3 號桶。

**順便讓擴容變便宜**：桶數翻倍後遮罩多一個位元，每個元素只有「留在原桶」或「搬到原編號 + 舊桶數」兩種結果，只檢查那一個位元，不必重算 hashCode。

> ⚠ `(n - 1) & hash` 只有桶數是 2 的次方才等於取餘數。n = 10 時 n - 1 = 1001，桶編號只會是 0、1、8、9，其他桶永遠是空的。

```java
int h = key.hashCode();
// 高 16 位元折下來混進低 16 位元
int spread = h ^ (h >>> 16);
// 桶數是 2 的次方時等同取餘數
int index = (n - 1) & spread;
```

一句話：桶數取 2 的次方，用遮罩算桶編號又快又不怕負數；但遮罩只看低位元，所以要先把高位元攪進來。

### 這東西用在哪

**對寫程式的人**：自訂 class 當 key 時，hashCode 的低位元要有變化（例如回傳 id * 1024 在小 id 時會全進 0 號桶）；遮罩法也避開 `h % n` 在 Java 可能得到負數的問題。

**對產品端的人**：資料分片（分到多台機器／資料庫）也有同樣問題，編號有規律就可能全落在同一台。分得均勻時，資料從一百筆長到一萬筆速度幾乎不變；分得不均時，整體被最擠的那一台拖慢。可以問工程師：資料分到各桶或各台的數量有檢查過嗎？資安上有 hash flooding 攻擊：故意送大量撞同桶的輸入。

### LeetCode · [#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

**題目在說什麼**：不用內建 HashMap，自己做出 put / get / remove，key 與 value 都是 0 到 10^6 的整數，get 找不到回傳 -1。

**解法步驟**：
1. 準備 1024 個桶，每個桶是一串清單，存 {key, value}。
2. 桶編號用 `key & 1023`。
3. put：掃桶，有就更新，沒有就接在最後。
4. get：掃桶，找到回傳 value，否則 -1。
5. remove：掃桶，移除 key 相同的配對。

**複雜度**：時間 O(n / 1024)，桶數固定時漸進仍是 O(n)，因為每次只掃一個桶，平均長度是元素數除以桶數。空間 O(1024 + n)，固定桶數加每個鍵值對各一格。

```java
class MyHashMap {
    private static final int N = 1024;
    private List<int[]>[] buckets;

    @SuppressWarnings("unchecked")
    public MyHashMap() {
        buckets = new List[N];
        for (int i = 0; i < N; i++) {
            buckets[i] =
                new LinkedList<>();
        }
    }

    private List<int[]> bucket(int k) {
        // N 是 2 的次方，遮罩等同取餘數
        return buckets[k & (N - 1)];
    }

    public void put(int key, int val) {
        List<int[]> b = bucket(key);
        for (int[] e : b) {
            if (e[0] == key) {
                e[1] = val;
                return;
            }
        }
        b.add(new int[]{key, val});
    }

    public int get(int key) {
        for (int[] e : bucket(key)) {
            if (e[0] == key) {
                return e[1];
            }
        }
        return -1;
    }

    public void remove(int key) {
        bucket(key)
            .removeIf(e -> e[0] == key);
    }
}
```

### 術語表

| 術語 | 中文 | 白話定義 |
|---|---|---|
| Bitwise AND (&) | 位元 AND | 二進位逐位比對，兩邊都是 1 才得 1 |
| Bit mask | 位元遮罩 | 用 AND 只留下某幾個位元，其餘清成 0 |
| Power of two | 2 的次方 | 1、2、4、8、16⋯⋯；減 1 後二進位是連續的 1 |
| XOR (^) | 互斥或 | 位元相同得 0、不同得 1，用來混合資訊 |
| Unsigned right shift (>>>) | 無號右移 | 二進位整串右推，左邊補 0 |
| Hash spreading | 雜湊擾動 | 取桶前先把高位元混進低位元 |
| Chaining | 鏈式位址 | 每個桶底下掛一串清單，撞同桶的 key 接在後面 |
