## Binary Search Tree：中序走訪的有序性與插入刪除 · 第 3 步

### Why O(height)? When a BST Degrades

![二元搜尋樹退化](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_tree/binary_search_tree.assets/bst_degradation.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

原文指出：平衡時各項操作都是對數階；若不斷插入刪除，樹可能退化成鏈結串列，各種操作退化為 O(n)。只有在高頻新增、低頻查詢刪除的場景，陣列才比二元搜尋樹更有效率。

**成本算什麼**：查詢、插入、刪除最多走「樹高」步，所以成本是 O(h)，不是 O(n)。

**好情況與壞情況**：平衡樹高約 log₂ n（一百萬筆約 20 層）；依序插入 1、2、3、4、5 會一直往右掛，樹高 = n，成本 O(n)。

**中序走訪不受影響**：每個節點碰一次，仍是 O(n) 且結果仍是升序；退化只讓找、插、刪變慢。

**注意**：BST 本身不保證 O(log n)，要保證需用 AVL、紅黑樹等自平衡樹。Java 的 TreeMap／TreeSet 底層是紅黑樹。

```java
int steps(TreeNode root, int num) {
    TreeNode cur = root;
    int count = 0;
    while (cur != null) {
        // 每看一個節點就算一步
        count++;
        if (cur.val < num)
            cur = cur.right;
        else if (cur.val > num)
            cur = cur.left;
        else
            break;
    }
    // 最多等於樹高
    return count;
}
```

### 這東西用在哪

- 寫程式的人：需要動態且隨時有序、要找第 k 小、前後一個、範圍查詢時用有序的樹；手刻裸 BST 遇到已排序輸入會退化，遞迴還可能 StackOverflowError。
- 產品端：即時排行榜、價格區間篩選等功能背後常是有序樹；若不平衡，大量匯入已排序資料後會越來越慢。可問工程師：這個結構會自己保持平衡嗎？最壞是 log n 還是 n？

### LeetCode [#230 Kth Smallest Element in a BST](https://leetcode.com/problems/kth-smallest-element-in-a-bst/)（Medium）

**題意**：回傳 BST 中第 k 小的值。

**解法**：
1. 中序走訪得到升序，第 k 個被走到的就是第 k 小。
2. 用 count 計數，輪到「根」時加 1。
3. count 等於 k 時記下值。
4. 找到後立刻停止。

**複雜度**：時間 O(h + k)（先沿左邊走 h 層，再走 k 個節點），最壞 O(n)；空間 O(h)（遞迴堆疊），退化時 O(n)。

```java
class Solution {
    int count = 0;
    int ans = 0;

    public int kthSmallest(
            TreeNode root, int k) {
        inorder(root, k);
        return ans;
    }

    private void inorder(
            TreeNode node, int k) {
        if (node == null) return;
        // 左
        inorder(node.left, k);
        // 左邊已找到就不必再往下
        if (count >= k) return;
        // 根：算第幾個
        count++;
        if (count == k) {
            ans = node.val;
            return;
        }
        // 右
        inorder(node.right, k);
    }
}
```

### 術語表

| 術語 | 白話定義 |
|---|---|
| Height 樹高 | 從根往下最長那條路有幾層 |
| Balanced 平衡 | 左右高度差不多，樹很矮 |
| Degeneration 退化 | 樹變成一條斜線，效能同鏈結串列 |
| Linked list 鏈結串列 | 每個節點只連下一個，排成一長串 |
| O(log n) 對數階 | 資料翻倍只多一步 |
| Self-balancing tree 自平衡樹 | 會自己調整形狀避免退化，如 AVL、紅黑樹 |
