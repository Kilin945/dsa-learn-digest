## Big-O 複雜度：怎麼估一段程式的快慢 · 第 4 步

### 概念：Simplifying Big-O — Drop Constants & Non-Dominant Terms

Big-O 只關心「n 很大時，哪一項長得最快」：

1. **丟常數**：O(2n) → O(n)、O(3n²) → O(n²)
2. **丟低階項**：O(n² + n) → O(n²)、O(n + log n) → O(n)

關鍵前提：
- **循序執行**（一段迴圈跑完換下一段）→ 時間**相加**：O(n) + O(n) = O(2n) → 化簡為 O(n)
- **巢狀執行**（迴圈裡包迴圈）→ 時間**相乘**：O(n) × O(n) = O(n²)

這也解釋了為什麼 Two Sum 暴力解（巢狀雙迴圈）是 O(n²)，而昨天的 HashMap 解法（單層迴圈 + O(1) 查詢）是 O(n)。

```java
// 兩個「循序」執行的迴圈：時間相加 O(n) + O(n) = O(2n)
int max = arr[0];
for (int i = 0; i < arr.length; i++) {      // 掃一次 n 個元素：O(n)
    if (arr[i] > max) max = arr[i];
}

int sum = 0;
for (int i = 0; i < arr.length; i++) {      // 又掃一次 n 個元素：O(n)
    sum += arr[i];
}
// 兩段迴圈是先後執行，不是巢狀，次數相加：n + n = 2n
// 化簡後拿掉常數 2 → O(n)，不是 O(n²)！
```

**練習題**：[#1394 Find Lucky Integer in an Array](https://leetcode.com/problems/find-lucky-integer-in-an-array/)（Easy）— 練習兩個循序 O(n) 迴圈化簡成 O(n)。

### 術語表

| 術語 | 定義 |
|---|---|
| Dominant term（主導項） | Big-O 式子裡 n 很大時長得最快的那一項，決定整體複雜度 |
| Lower-order term（低階項） | 比主導項成長慢很多的項，n 變大後可忽略 |
| Sequential vs nested（循序 vs 巢狀） | 循序迴圈時間相加，巢狀迴圈時間相乘，結果完全不同 |
