## 字串 String：不可變性、StringBuilder 與字元陣列的關係 · 第 3 步

### char[] ↔ String：轉過去改，再轉回來

String 不可變，StringBuilder 是為了「組出一整串新內容」而生；但如果要做的事情是「直接改某個位置上的字元」（交換頭尾字元、逐字判斷回文），這兩個工具都不太順手。做法是先呼叫 `toCharArray()`，把字串內容複製成一份 `char[]`（字元陣列，一排可以用索引直接取用、也能直接覆寫內容的容器），改完之後再用 `new String(陣列)` 把它變回字串。

**關鍵事實**：`toCharArray()` 給你的是一份全新複製出來的陣列，跟原本的 String 物件是兩份不同的資料。改動這份陣列完全不會影響原本那個字串——它仍然不可變，一個字都沒被動到，直到你用 `new String()` 建出一個全新的字串物件取代它。

> ⚠ 最容易搞錯的地方：很多人以為改了 `toCharArray()` 拿到的陣列，原本那個 String 也會跟著變。實際上那是一份複製品，String 的不可變性完全沒被打破。

```java
// 轉成字元陣列（複製一份）
char[] arr = str.toCharArray();
// 直接修改陣列裡的某個位置
arr[0] = 'H';
// 轉回 String（一樣是複製）
String result = new String(arr);
```

### 這東西用在哪

**對寫程式的人**：需要用雙指標直接對字串裡的位置做交換、或要逐字判斷／修改（反轉字串、判斷回文、字元計數），用 `char[]`；只是要「從頭到尾組出一個新字串」，用 `StringBuilder` 更合適。硬要在 String 上做原地修改會直接被不可變性擋下（沒有 `setCharAt`），逼你走 `char[]` 或 `StringBuilder` 之一。

**對產品端的人**：看到「反轉輸入文字」「回文偵測」「字謎／易位詞比對」這類逐字元比較或交換的功能，背後八成是把字串轉成字元陣列在做迴圈比對；耗時跟輸入文字長度成正比，不會突然爆掉。

### LeetCode #344 Reverse String（Easy）

[題目連結](https://leetcode.com/problems/reverse-string/)

題目：給一個字元陣列，原地把它反過來排列。

解法：雙指標 left/right 從兩端往中間夾，逐一交換字元，直到相遇。

複雜度：時間 O(n)（每個字元交換一次），空間 O(1)（只用兩個指標與一個暫存變數）。

```java
public void reverseString(char[] s) {
    int left = 0;
    int right = s.length - 1;
    // 頭尾指標，一步步往中間夾
    while (left < right) {
        // 交換頭尾的字元
        char temp = s[left];
        s[left] = s[right];
        s[right] = temp;
        left++;
        right--;
    }
}
```

### 術語表

- **toCharArray()**（字串轉字元陣列）：把 String 內容複製一份成 char[]。
- **char[]**（字元陣列）：可用索引直接存取／覆寫的字元容器，是可變的。
- **new String(char[])**（陣列轉回字串）：把 char[] 內容複製出來，包成新的 String。
- **in-place**（原地修改）：直接在原本傳進來的容器裡修改，不額外配置新容器。
- **two pointers**（雙指標）：同時用兩個索引在同一容器不同位置移動，通常一頭一尾往中間夾。
