## 雜湊函式與負載因子：hashCode、擴容與 rehash · 第 3 步

### What Makes a Good Hash Function

![雜湊衝突的最佳情況與最差情況](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_algorithm.assets/hash_collision_best_worst_condition.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

圖解：同一種鏈式位址雜湊表的兩個極端。最佳情況是鍵值對均勻分佈在各個桶中，查詢效率最好；最差情況是所有鍵值對都存到同一個桶，時間複雜度退化為 O(n)。開放定址與鏈式位址只能保證衝突時雜湊表正常運作，無法減少衝突發生，要減少衝突只能靠雜湊函式本身。

**好的雜湊函式三特性**

- 確定性（deterministic）：同一個 key 結果永遠一樣。
- 效率：計算要快。
- 均勻分佈（uniform distribution）：key 平均散到各桶，這是決定雜湊表快慢的關鍵。

**壞設計：加總字元**

"abc" 與 "cba" 加總都是 294，所有字母相同、排列不同的字串都撞同一桶，因為它完全不在乎順序。

**改良：每步乘 31（多項式雜湊）**

每讀一個字元就 `h = 31 * h + c`，位置影響結果。"abc" = 96354，"cba" = 98274。這就是 Java `String.hashCode()` 的做法。

> ⚠ 雜湊函式只能減少衝突，不能消除。雜湊值不同，取餘數後仍可能同桶（96354 與 98274 對 16 取餘數都是 2）；雜湊值相同則一定同桶。

```java
// 壞：只加總，順序無關
static int sumHash(String s) {
    int h = 0;
    for (char c : s.toCharArray()) {
        h += c;
    }
    return h;
}

// 好：每步乘 31，順序有影響
static int polyHash(String s) {
    int h = 0;
    for (char c : s.toCharArray()) {
        h = 31 * h + c;
    }
    return h;
}
```

一句話：雜湊函式的好壞看散得均不均勻，只加總這種不管順序的算法會讓一大堆 key 撞在同一桶。

### 這東西用在哪

**對寫程式的人**：自訂 class 當 HashMap key 時要同時覆寫 equals 與 hashCode，可用 `Objects.hash(...)`。hashCode 回傳固定值或只用幾乎都一樣的欄位，程式仍正確但資料量大時查詢退化成 O(n)，且沒有任何錯誤訊息。

**對產品端的人**：帳號是否存在、商品去重、依代碼查資料等「輸入一個東西立刻回答」的功能多半是雜湊表，資料散得均勻時從百筆到千萬筆速度幾乎不變；但資料天生集中（例如大量相同分類碼）會在某個規模突然變慢。對外開放輸入的欄位還要防雜湊洪水攻擊（hash flooding）。可以問工程師：拿來當查找依據的欄位分佈夠均勻嗎？

### 動手寫 · LeetCode

[#49 Group Anagrams](https://leetcode.com/problems/group-anagrams/)（Medium）

**題目在說什麼**：把字母組成相同、只是排列不同的字串分成同一組。

**怎麼用今天學的東西解**

1. 準備 HashMap，key 是分組代號，value 是該組字串清單。
2. 每個字串把字母排序，排序結果當分組代號。
3. 用 computeIfAbsent 取出清單並加入原字串。
4. 回傳 map 所有 value。

**複雜度**

- 時間 O(n · k log k)：n 個字串各排序一次，每個長度 k 排序要 k log k。
- 空間 O(n · k)：所有字串與排序副本 key 都要存。

```java
import java.util.*;

class Solution {
    public List<List<String>> groupAnagrams(
            String[] strs) {
        Map<String, List<String>> map =
            new HashMap<>();
        for (String s : strs) {
            char[] c = s.toCharArray();
            // 同一組字母排序後相同
            Arrays.sort(c);
            String key = new String(c);
            // 沒有這組就先建空清單
            map.computeIfAbsent(key,
                k -> new ArrayList<>())
                .add(s);
        }
        return new ArrayList<>(map.values());
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Deterministic | 確定性 | 同一輸入不管算幾次輸出都一樣 |
| Uniform distribution | 均勻分佈 | key 平均散到各桶 |
| Hash collision | 雜湊衝突 | 不同 key 算到同一桶，只能減少無法避免 |
| Polynomial hash | 多項式雜湊 | 每步乘固定數再加字元，讓位置影響結果，Java 字串用 31 |
| Anagram | 字母異位詞 | 字母相同、排列不同的字串 |
