## 雜湊函式與負載因子：hashCode、擴容與 rehash · 第 6 步

### Presizing: avoid rehash by choosing the initial capacity

**擴容不是免費的**：HashMap 預設 16 個桶，負載因子超過 0.75 就翻倍並 rehash。放 100 萬筆要翻十幾次，每次都搬一遍所有元素。

**先算好容量，一次到位**：門檻 = 桶數 × 0.75，所以容量要 ≥ n ÷ 0.75。公式：`(int) (n / 0.75f) + 1`。整批放入仍是 O(n)，但少掉十幾次 O(n) 的搬家。

**但別開過頭**：空桶也佔記憶體，也拖慢走訪。數量估不準就用預設值。

> ⚠ `new HashMap<>(100)` 會進位成 128 桶，門檻 96，放到第 97 筆就擴容。容量參數是桶數不是元素數。Java 19+ 可用 `HashMap.newHashMap(n)`。

```java
int n = 1_000_000;
// 預設：16 桶起跳，翻倍十幾次
Map<Integer,Integer> a =
    new HashMap<>();
// 預先給容量：一次到位
Map<Integer,Integer> b =
    new HashMap<>(
        (int) (n / 0.75f) + 1);
// Java 19+ 可以直接這樣寫
Map<Integer,Integer> c =
    HashMap.newHashMap(n);
```

### 這東西用在哪

- 寫程式的人：批次轉 Map、啟動載入快取等「數量已知」的場景，多傳一個容量參數即可；不預先配置不會錯，只是多做搬家且某次 put 會突然變慢。
- 產品端：大量匯入或剛重啟時偶爾卡一下，可能是擴容那一次寫入要搬全部資料；資料越大卡越久。可問工程師「這批資料幾筆、有沒有預先配置容量」。

### LeetCode

[#217 Contains Duplicate](https://leetcode.com/problems/contains-duplicate/)（Easy）

- 題目：陣列中有任何數字出現兩次以上就回傳 true。
- 解法：用預先配置容量的 HashSet，逐一 add，回傳 false 代表重複。
- 複雜度：時間 O(n)（走一遍，add 平均 O(1)）；空間 O(n)（最壞存 n 個數字）。

```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public boolean containsDuplicate(
            int[] nums) {
        int n = nums.length;
        // 先算好容量，避免中途擴容
        // 公式：n 除以 0.75 再加 1
        int cap = (int) (n / 0.75f) + 1;
        Set<Integer> seen =
                new HashSet<>(cap);
        for (int x : nums) {
            // add 回傳 false 代表已存在
            if (!seen.add(x)) {
                return true;
            }
        }
        return false;
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| initial capacity | 初始容量 | 建立時一開始的桶數，Java 預設 16 |
| threshold | 擴容門檻 | 桶數 × 負載因子 |
| presizing | 預先配置容量 | 已知數量時先開夠容量 |
| resize / rehash | 擴容／重新分桶 | 桶數翻倍並重新放置所有元素，約 O(n) |
