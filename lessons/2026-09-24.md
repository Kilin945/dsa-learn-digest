## Linked List 基礎：節點、指標與 dummy head 技巧 · 第 3 步

### Dummy Head Node（虛擬頭節點）

**改指標，改的到底是誰**
昨天學到插入是改兩個引用，刪除也是同樣的道理：只要改「前一個節點」的 next 引用，讓它直接指向被刪除節點的下一個，就等於跳過了那個節點，不需要搬動任何資料。真正被改動的其實是被刪除節點「前面那一個」的引用，不是被刪除節點自己。

**頭節點沒有「前一個」**
如果要刪除或插入的剛好是串列的第一個節點，它前面沒有任何節點，所以沒有「前一個節點的引用」可以改，你能改的只剩下外部那個記著「頭節點是誰」的變數本身——這是完全不同的一種操作，代表你得為「處理第一個節點」另外寫一段特例程式碼。

**假頭節點：先送一個不算數的節點上場**
解法是在真正的頭節點前面，多接一個不裝真正資料的假節點（dummy head），然後永遠讓外部指標指著這個假節點。這樣「處理第一個節點」就變成了跟處理中間任何節點完全一樣的一般情況，因為連真正的頭節點也有「前一個節點」（dummy）可以改了。

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

圖中的 P 是要被刪除的節點，刪除節點「只需改變一個節點的引用（指標）即可」——把 P 前面那個節點的指標改成指向 P 後面那個節點，P 就被跳過去了。刪除後 P 自己仍指著舊鄰居，但已經沒有任何人從頭走訪得到 P，所以 P 已經不算是這個鏈結串列的一部分。

⚠ **最容易搞錯的地方**：dummy 本身不是真正的資料，它的 value 完全不會被用到；處理完之後一定要回傳 `dummy.next`，不是 dummy 自己。

```java
class ListNode {
    int val;
    ListNode next; // 指向下一個節點的引用
    ListNode(int val) {
        this.val = val;
    }
}

// 建立假頭節點，value 不會被用到
ListNode dummy = new ListNode(0);
dummy.next = head;

// 之後都用 dummy 操作，不必再判斷 head 是否為 null
ListNode cur = dummy;
```

### 這東西用在哪

**對寫程式的人**：只要操作有可能動到串列第一個節點（插入最前面、刪除條件可能包含第一筆、合併兩串列），就該架 dummy head，讓所有邏輯共用一套程式碼。漏用的下場通常是「刪第一筆」這條路徑單獨壞掉，其他測試都正常，非常難抓。

**對產品端的人**：聽到「頭節點邊界情況」多半就是這個問題。這個技巧完全不影響清單能撐多大、多快——操作的時間複雜度沒有改變，它解決的是正確性問題不是規模問題。可以直接問工程師「刪掉清單第一筆會不會壞」。

### 動手寫 · LeetCode

[#203 Remove Linked List Elements](https://leetcode.com/problems/remove-linked-list-elements/)（Easy）

**題目**：給定鏈結串列頭節點與數字 val，刪掉所有值等於 val 的節點（含可能的第一個節點），回傳新頭節點。

**解法步驟**：
1. 建立 dummy head，dummy.next 指向真正的 head。
2. 用 cur 從 dummy 開始走訪，檢查 cur.next.val 是否等於 val。
3. 是就讓 cur.next = cur.next.next（跳過該節點）；否則 cur 前進一步。
4. 回傳 dummy.next。

**複雜度**：時間 O(n)（只走訪一次，每個節點最多檢查一次）；空間 O(1)（只多一個 dummy 節點）。

```java
class Solution {
    public ListNode removeElements(ListNode head, int val) {
        ListNode dummy = new ListNode(0); // 假頭節點
        dummy.next = head;
        ListNode cur = dummy;
        while (cur.next != null) {
            if (cur.next.val == val) {
                cur.next = cur.next.next; // 跳過該節點＝刪除它
            } else {
                cur = cur.next;
            }
        }
        return dummy.next; // 回傳 dummy 之後的節點
    }
}
```

### 今日術語表

| 術語 | 定義 |
|---|---|
| Dummy Head Node（虛擬頭節點） | 接在真正頭節點前面、不裝真正資料的假節點，讓「處理第一個節點」也能套用一般的「改前一個節點的引用」邏輯 |
| Sentinel Node（哨兵節點） | Dummy head 的另一個常見說法，強調它是站崗用、不參與真正資料運算的節點 |
| Edge Case（邊界情況） | 程式邏輯裡「最前面／最後面／空的」這類特殊位置，最容易被漏掉、也最容易出 bug 的地方 |
