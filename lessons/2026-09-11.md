## 空間複雜度：記憶體也要算，遞迴呼叫堆疊的隱藏成本 · 第 5 步

### 對數階空間複雜度 O(log n)：分治遞迴每次砍半

昨天教的線性遞迴，每呼叫一次只讓問題規模少 1，要呼叫 n 次才結束，堆疊深度 O(n)。
今天的模式是每次遞迴呼叫都讓問題規模「減半」（例如二分搜尋、快速冪、合併排序），
只需要呼叫約 log2(n) 次就能結束，堆疊深度是 O(log n)，比 O(n) 淺得多。

跟前一天教的「滿二元樹」分裂遞迴要分開看：滿二元樹每次呼叫都分裂成兩個子呼叫，
兩條分支都要展開，總節點數是指數階 O(2^n)；而分治遞迴每次呼叫只選一半繼續走，
另一半直接丟掉，所以堆疊深度只需要 O(log n)。

```java
void logRecur(int n) {
    if (n <= 1) return;
    // n 減半，遞迴深度只需 O(log n)
    logRecur(n / 2);
}
```

⚠ 容易搞錯：不是所有遞迴的堆疊深度都是 O(n)，要看每次呼叫讓問題規模「少多少」——
每次減 1 是 O(n)，每次砍半是 O(log n)。

### 這東西用在哪

- **對寫程式的人**：處理「每次都能把範圍縮小一半」的情境（二分搜尋、分治排序、快速冪），
  用遞迴寫比維護一堆變數的迴圈版本更直覺；深度只有 O(log n)，資料再大也不會 stack overflow。
- **對產品端的人**：功能背後是「二分搜尋」或「分治法」，代表資料量長十倍，速度幾乎不變慢——
  是效能最好、最不用擔心規模變大的一種。

### LeetCode #50 Pow(x, n)（Medium）

[https://leetcode.com/problems/powx-n/](https://leetcode.com/problems/powx-n/)

用「快速冪」：x^n = (x^(n/2))^2（偶數）或再乘一個 x（奇數），每次遞迴指數減半，
負指數先轉成 1/x 的正指數版本再套用同一套遞迴。

- 時間 O(log n) — 每次呼叫指數減半，只需要 log2(n) 次呼叫。
- 空間 O(log n) — 同一時間堆疊上未 return 的呼叫只有 log2(n) 層。

```java
class Solution {
    public double myPow(double x, int n) {
        long N = n;
        if (N < 0) {
            x = 1 / x;
            N = -N;
        }
        return fastPow(x, N);
    }

    private double fastPow(double x, long n) {
        if (n == 0) return 1.0;
        // n 減半，遞迴深度 O(log n)
        double half = fastPow(x, n / 2);
        if (n % 2 == 0) {
            return half * half;
        }
        return half * half * x;
    }
}
```

### 今日術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Logarithmic | 對數階 | 資料量每變 10 倍，只多做約 3～4 次工作 |
| Divide and conquer | 分治法 | 把問題拆成更小子問題（通常砍半），分別解決再合併 |
| Recursion depth | 遞迴深度 | 同一時間堆疊上還沒 return 的呼叫層數 |
| Binary search | 二分搜尋 | 每次把搜尋範圍砍半的搜尋方法 |
