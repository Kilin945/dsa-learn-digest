## Heap / PriorityQueue：完全二元樹、上浮下沉與 Top-K · 第 1 步

### Heap = Complete Binary Tree + Ordering Rule

堆積就是「排成陣列的完全二元樹」，再加上一條父子之間的大小規則。

![小頂堆積與大頂堆積](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_heap/heap.assets/min_heap_and_max_heap.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

- 形狀：必須是完全二元樹（除最後一層外每層排滿，最後一層靠左，沒有空洞）。
- 小頂堆積（min heap）：任意節點的值小於等於子節點，最小值在根。
- 大頂堆積（max heap）：任意節點的值大於等於子節點，最大值在根。
- 規則只比父親和直屬孩子。

![堆積的表示與儲存](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_heap/heap.assets/representation_of_heap.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

- 完全二元樹沒有空洞，適合用陣列儲存，不需要指標。
- 索引公式：左子 2i + 1、右子 2i + 2、父 (i - 1) / 2（向下整除）；索引越界代表節點不存在。
- 例：[9, 7, 8, 3, 5, 6] 是大頂堆積。索引 1（值 7）的左子是索引 3、右子是索引 4、父是索引 0；索引 2（值 8）的右子索引 6 超出範圍，不存在。
- 樹高約 log₂n：看最大（小）值 O(1)；之後會學的加入與拿走元素 O(log n)，因為只沿一條根到葉的路徑修補。

**⚠ 最容易搞錯**：堆積不是排好序的陣列，只有根保證是最大或最小。直接遍歷 PriorityQueue 不會得到有序結果，要一個一個 poll。

```java
int[] heap = {9, 7, 8, 3, 5, 6};

int left(int i) {
    return 2 * i + 1;
}

int right(int i) {
    return 2 * i + 2;
}

int parent(int i) {
    return (i - 1) / 2;
}

// Java 內建優先佇列，預設是小頂堆積
PriorityQueue<Integer> pq =
    new PriorityQueue<>();
pq.offer(5);
pq.offer(1);
pq.offer(3);
// peek 看最小值（這裡會得到 1）
pq.peek();
```

一句話：堆積 = 完全二元樹 + 父子大小規則，用陣列存、靠 2i+1、2i+2 找孩子，根永遠是最大或最小。

深入官方文件：[Java PriorityQueue API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/PriorityQueue.html)

### 這東西用在哪

**對寫程式的人**：需求是「一直有新資料進來，每次拿出目前最大或最小」就用堆積（PriorityQueue），例如任務排程、前 K 大、合併已排序串列、最短路徑。不必每次重新排序，從 O(n log n) 降到 O(log n)。但查某個值在不在、刪中間元素都是 O(n)；Java 預設小頂堆積，要大的先出得傳 Comparator。

**對產品端的人**：「永遠先處理最緊急的一筆」「只顯示前 10 名」背後多半是堆積。一百筆約幾步、一百萬筆也只要約二十步，規模很能撐。但它只保證第一名正確，若需求是「看第 500 名」或「完整排行榜任意翻頁」，就需要另外排序或換結構，工期要重估。可問工程師：「這個功能只需要第一名，還是要完整排序？」

### 動手寫 · LeetCode

[#1046 Last Stone Weight](https://leetcode.com/problems/last-stone-weight/)（Easy）

**題目在說什麼**：每回合挑最重的兩顆石頭互撞，一樣重都消失，不一樣重則剩下重量差放回；重複到剩一顆或零顆，回傳剩下的重量（沒有回傳 0）。

**怎麼用今天學的東西解**

1. 每回合要取最重的，用大頂堆積。
2. Java 預設小頂堆積，傳 Collections.reverseOrder() 反轉。
3. 所有石頭 offer 進堆。
4. 堆內多於一顆時，poll 兩次得 a ≥ b。
5. a 不等於 b 就把 a - b 放回。
6. 堆空回傳 0，否則回傳 peek。

**複雜度**

- 時間 O(n log n)：每回合至少少一顆，最多約 n 回合，每回合 poll 與 offer 各 O(log n)。
- 空間 O(n)：所有石頭都存在堆積裡。

```java
import java.util.*;

class Solution {
    public int lastStoneWeight(
            int[] stones) {
        // Java 預設是小頂堆積
        // 所以要反向排序成大頂堆積
        Comparator<Integer> rev =
            Collections.reverseOrder();
        PriorityQueue<Integer> pq =
            new PriorityQueue<>(rev);
        for (int s : stones) {
            pq.offer(s);
        }
        while (pq.size() > 1) {
            // 每次拿出最重的兩顆
            int a = pq.poll();
            int b = pq.poll();
            if (a != b) {
                pq.offer(a - b);
            }
        }
        if (pq.isEmpty()) return 0;
        return pq.peek();
    }
}
```

### 今日術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Heap | 堆積 | 一種完全二元樹，父子之間符合固定大小規則 |
| Binary Tree | 二元樹 | 每個節點最多兩個子節點的樹 |
| Complete Binary Tree | 完全二元樹 | 除最後一層外排滿，最後一層靠左，無空洞 |
| Min Heap | 小頂堆積 | 任意節點 ≤ 子節點，最小值在根 |
| Max Heap | 大頂堆積 | 任意節點 ≥ 子節點，最大值在根 |
| Root / Leaf | 根／葉節點 | 根是最上面的節點；葉是沒有孩子的節點 |
| Index | 索引 | 陣列格子的編號，從 0 開始 |
| Pointer | 指標 | 記錄另一個節點位置的欄位；堆積改用索引公式取代 |
| PriorityQueue | 優先佇列 | 每次取出優先度最高的元素；Java 用堆積實作，預設小的先出 |
