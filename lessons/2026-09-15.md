## 迭代與遞迴：兩種重複的形式、呼叫堆疊與尾遞迴 · 第 4 步

### Tail Recursion（尾遞迴）

一般遞迴是「先呼叫、後加總」：每一層要等下一層把結果算出來、傳回來後，才把自己這份數字加上去——這個「加」的動作發生在函式一層層返回（「迴」）的過程中。

尾遞迴（tail recursion）反過來：先把加總做完，再往下一層呼叫，做法是多帶一個累加器參數（例如 `res`）把目前算到的結果往下傳；等碰到終止條件時答案早就算好了，剩下的「迴」只是把答案原封不動往上傳，不需要再做任何計算。

一般遞迴在「迴」的時候還要做事，所以每一層返回後系統都得記得上一層的上下文；尾遞迴呼叫是函式返回前的最後一個動作，返回後不用再執行任何程式碼，理論上系統可以直接捨棄這一層的堆疊幀，這個優化叫做「尾呼叫優化（tail call optimization，TCO）」。

> ⚠ Java 的 JVM 目前不會自動做尾呼叫優化。就算把程式碼寫成尾遞迴形式，在 Java 裡一樣會逐層佔用呼叫堆疊，深度太深一樣可能 stack overflow。尾遞迴在 Java 裡賺到的是邏輯乾淨，不是記憶體；真的擔心深度太深，該直接改寫成迴圈。

這個主題到此告一段落：迭代是用迴圈把重複次數講清楚；遞迴是函式呼叫自己、把大問題拆成一樣的小問題，靠終止條件、遞迴呼叫、返回結果三件事運作；每次呼叫都在呼叫堆疊上疊一層堆疊幀，疊太深就是遞迴深度過大、可能堆疊溢位；尾遞迴則是把加總動作提前做完的特殊寫法。

```java
// 一般遞迴（先前教過）：加總動作在「迴」的時候才做
int recurSum(int n) {
    if (n == 0) return 0;
    return n + recurSum(n - 1);
}

// 尾遞迴：多一個累加參數 res，加總動作在「遞」的時候先做完
int tailSum(int n, int res) {
    if (n == 0) {
        return res;
    }
    return tailSum(n - 1, res + n);
}
```

### 這東西用在哪

**對寫程式的人**：尾遞迴的想法在 Scala、Kotlin（`tailrec`）、Scheme 這類語言裡是真的有用的，編譯器會把它改寫成迴圈執行。但在 Java 裡，就算寫成尾遞迴的形狀，JVM 也不會幫你優化，堆疊還是一層層往上疊。真的擔心遞迴深度深，比較務實的做法是直接改寫成 for/while 迴圈搭配變數手動累加。

**對產品端的人**：聽到「這個功能底層是用遞迴實作」，可以追問「這個遞迴會呼叫自己幾層，跟資料的什麼屬性有關」——例如組織架構分得越深，遞迴呼叫層數就越多，深到某個程度可能直接讓伺服器壞掉，而不只是變慢。

### 動手寫：[#1979 Find Greatest Common Divisor of Array](https://leetcode.com/problems/find-greatest-common-divisor-of-array/)（Easy）

給一個整數陣列，找出最大值與最小值，回傳兩者的最大公因數（GCD）。

解法：先用迴圈找出最大值 mx、最小值 mn（迭代），再對兩者做輾轉相除法求 GCD：`gcd(a, b)` 若 `b == 0` 回傳 `a`，否則回傳 `gcd(b, a % b)`——這個函式本身天生就是尾遞迴，呼叫自己是整個函式唯一、也是最後的動作。

複雜度：時間 O(n + log(min(mx,mn)))，找最大最小值 O(n)，輾轉相除法呼叫次數是對數等級；空間 O(log(min(mx,mn)))，因為 Java 沒有 TCO，遞迴深度等於呼叫次數。

```java
class Solution {
    public int findGCD(int[] nums) {
        int mx = nums[0], mn = nums[0];
        for (int x : nums) {
            mx = Math.max(mx, x);
            mn = Math.min(mn, x);
        }
        return gcd(mx, mn);
    }

    // 尾遞迴：呼叫本身就是最後一步
    private int gcd(int a, int b) {
        if (b == 0) {
            return a;
        }
        return gcd(b, a % b);
    }
}
```

### 術語表

- **Tail Recursion 尾遞迴**：遞迴呼叫是函式返回前的最後一個動作，呼叫前該做的計算都已做完。
- **Tail Call Optimization TCO 尾呼叫優化**：編譯器/直譯器把尾遞迴改寫成迴圈、不佔額外堆疊；Java 不會自動做。
- **Accumulator 累加器**：尾遞迴裡多帶的參數（如 `res`），提前存放目前算到的結果。
- **Euclidean Algorithm 輾轉相除法**：`gcd(a, b) = gcd(b, a % b)` 反覆縮小求最大公因數的演算法。
