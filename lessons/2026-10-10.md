## HashMap / HashSet：O(1) 查找的原理與代價 · 第 2 步

### Hash Collision & Separate Chaining

![雜湊衝突示例](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_map.assets/hash_collision.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

**圖說**：原文的簡單雜湊函式在 key 後兩位相同時輸出相同，學號 12836 與 20336 後兩位都是 36，兩個學號指向了同一個姓名，這是不對的。這種多個輸入對應同一輸出的情況叫雜湊衝突（hash collision）。輸入空間（所有可能的 key）往往遠大於輸出空間（陣列所有索引），所以理論上一定存在衝突。

**衝突躲不掉**：key 的種類遠多於桶的數量，衝突是數量上必然發生的事（鴿籠原理），設計重點是撞了怎麼辦。

**解法：鏈結法（separate chaining）**：每個桶放一條串列，撞進同一桶的資料排在同一條串列上。查找時先跳到桶，再沿串列用 equals 比對 key。Java 的 HashMap 用的就是這種做法。

**代價**：查找成本是 O(1 + 鏈長)。分散得平均時鏈很短，平均 O(1)；全部撞進同一桶時鏈長為 n，退化成 O(n)。Java 8 之後單一桶的鏈超過 8 個會改成紅黑樹，最壞降為 O(log n)。減少衝突的另一招是擴容，下一步再教。

**易錯**：撞到同一個桶不代表 key 相同，找到桶後一定要用 equals 比對 key 本身。

### 這東西用在哪

- 寫程式：統計次數、去重、快取、建索引時選 HashMap / HashSet。自訂類別當 key 要同時覆寫 equals 與 hashCode 且兩者一致；hashCode 固定回傳 1 會讓所有資料撞進同一桶而退化。
- 產品端：精確查找（帳號、訂單編號）多半是雜湊表，資料量長大後單次查找仍很快；變慢的徵兆是資料分佈不平均。雜湊表不擅長範圍與排序查詢。資安：刻意製造大量衝突的 key 可使查找退化，即 hash flooding 攻擊。

### LeetCode · [#705 Design HashSet](https://leetcode.com/problems/design-hashset/)（Easy）

自己做一個集合，支援 add、remove、contains，key 為 0 到 10^6 的整數，不可用內建 HashSet。

解法：769 個桶（質數），每桶一條 LinkedList，桶編號為 key % 769；add 先確認沒有才加，remove 從該桶移除，contains 在該桶掃串列。

- 時間：每個操作平均 O(n/769)，即平均鏈長。
- 空間：O(769 + n)。

```java
class MyHashSet {
    private static final int N = 769;
    private List<Integer>[] bk;

    @SuppressWarnings("unchecked")
    public MyHashSet() {
        bk = new List[N];
        for (int i = 0; i < N; i++) {
            bk[i] = new LinkedList<>();
        }
    }

    private int idx(int key) {
        // 雜湊函式：取模得到桶編號
        return key % N;
    }

    public void add(int key) {
        List<Integer> b = bk[idx(key)];
        // 沒有才加，Set 不允許重複
        if (!b.contains(key)) {
            b.add(key);
        }
    }

    public void remove(int key) {
        List<Integer> b = bk[idx(key)];
        // 傳 int 會被當成索引
        b.remove(Integer.valueOf(key));
    }

    public boolean contains(int key) {
        List<Integer> b = bk[idx(key)];
        return b.contains(key);
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Hash collision 雜湊衝突 | 兩個不同的 key 算出同一個桶編號 |
| Separate chaining 鏈結法 | 每個桶放一條串列，撞進同一桶的資料都串在上面 |
| Bucket 桶 | 雜湊表陣列裡的一格 |
| Linked list 鏈結串列 | 資料一個接著一個串起來的清單 |
| Pigeonhole principle 鴿籠原理 | 東西比格子多時，至少有一格放到兩個以上 |
| equals / hashCode | hashCode 決定去哪個桶，equals 決定桶裡哪一筆是同一個 key |
