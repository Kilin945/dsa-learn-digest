## 雜湊衝突：鏈結法 chaining 與開放定址 open addressing · 第 3 步

### Load Factor & Resizing（負載因子與擴容）

**負載因子**（load factor）= 已存的鍵值對數 ÷ 桶子總數，代表雜湊表的擁擠程度。例如 16 個桶存 12 筆，負載因子 0.75。

**兩種做法的代價不同**

- 鏈式位址：負載因子可超過 1，平均鏈長約等於負載因子，平緩地變慢。
- 開放定址：負載因子不可能超過 1，且越接近 1 越糟。線性探查的教科書近似公式估計，查不存在的 key 平均探查桶數：負載因子 0.5 約 2.5、0.75 約 8.5、0.9 約 50。

**擴容（resize）**

超過門檻（Java HashMap 預設初始 16 桶、門檻 0.75）就開兩倍大的新陣列，把所有鍵值對重新放入。單次 O(n)，但每次翻倍，總搬運量不超過約 2n，攤銷（amortized）後每次 put 仍是 O(1)。

**易錯點**：擴容必須對每個 key 重新算桶號（rehash），因為桶號 = 雜湊值 % 桶數。例如雜湊值 17：16 個桶時在 1 號桶，32 個桶時在 17 號桶。

**一句話**：負載因子超過門檻就翻倍擴容並重算位置，偶爾一次 O(n)，攤銷後仍是 O(1)。

### 這東西用在哪

- 寫程式：已知筆數時建立 HashMap 就給足初始容量（約 預期筆數 ÷ 0.75），省掉中途多次擴容；擴容那次 put 會出現延遲尖峰。
- 產品端：功能平常很快、偶爾卡一下且間隔越來越長，可能是雜湊表擴容；雜湊表刻意留空位，比連續排列更吃記憶體，千萬級資料要先估記憶體。

### LeetCode：[#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

用鏈式位址實作 HashMap，並在負載因子超過 0.75 時擴容。時間平均 O(1)（鏈短、擴容攤銷），最壞 O(n)；空間 O(n)。

```java
class MyHashMap {
    private List<int[]>[] buckets;
    private int size = 0;

    public MyHashMap() {
        init(16);
    }

    private void init(int cap) {
        buckets = new List[cap];
        for (int i = 0; i < cap; i++) {
            buckets[i] =
                new LinkedList<>();
        }
    }

    private int idx(int k) {
        return k % buckets.length;
    }

    public void put(int k, int v) {
        var list = buckets[idx(k)];
        for (int[] p : list) {
            if (p[0] == k) {
                p[1] = v;
                return;
            }
        }
        list.add(new int[]{k, v});
        size++;
        // 負載因子超過 0.75 就擴容
        int cap = buckets.length;
        if (size > cap * 0.75)
            resize();
    }

    public int get(int k) {
        for (int[] p : buckets[idx(k)])
            if (p[0] == k) return p[1];
        return -1;
    }

    public void remove(int k) {
        var list = buckets[idx(k)];
        var it = list.iterator();
        while (it.hasNext()) {
            if (it.next()[0] == k) {
                it.remove();
                size--;
                return;
            }
        }
    }

    private void resize() {
        var old = buckets;
        init(old.length * 2);
        for (var list : old) {
            for (int[] p : list) {
                // 桶數變了，必須重算桶號
                int i = idx(p[0]);
                buckets[i].add(p);
            }
        }
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Load factor | 負載因子 | 已存的鍵值對數 ÷ 桶子總數，代表有多擠 |
| Capacity | 容量 | 雜湊表目前有幾個桶子 |
| Resize | 擴容 | 太擠時換成兩倍大的新表並搬資料 |
| Rehash | 重新雜湊 | 擴容時用新桶數重算每個 key 的桶號 |
| Amortized | 攤銷 | 把偶爾一次的大花費平均分攤到每次操作 |
