## 陣列 Array 與動態陣列 ArrayList：連續記憶體的代價與好處 · 第 2 步

### 概念：Insertion Cost: Shifting Elements

陣列是連續記憶體，每一格緊密相連、不能留空隙。昨天講的 random access（隨機存取）之所以能做到 O(1)，就是靠這個連續性，用位址公式直接算出目標位置。

但這個「緊密相連」也是代價來源：要在陣列**中間**插入或刪除一個元素，不能只動那一格，後面所有元素都要跟著往後（插入）或往前（刪除）搬一格，才能維持陣列連續、沒有空隙的規則，這個動作叫 **shifting（搬移）**。直接在原本記憶體位置上修改、不另外開新陣列，叫 **in-place（原地）** 操作。

最壞情況（**worst case**）是插入/刪除位置在陣列最前面（index 0），此時後面所有元素都要搬，若陣列有 n 個元素，最多要搬 n-1 次。

### 程式碼（暴力版：陣列中插入元素）

```java
// 在陣列 arr 的 index 位置插入 value
// n 是目前已使用的長度（陣列本身容量要夠大，這裡先假設夠）
static void insertAt(int[] arr, int n, int index, int value) {
    // 從最後一格開始，把每個元素往後搬一格，空出 index 這格
    for (int i = n; i > index; i--) {
        arr[i] = arr[i - 1]; // 搬移動作：worst case 要搬 n 次
    }
    arr[index] = value; // 空位騰出後才塞入新值
}
```

### 複雜度分析

- 這段程式碼是 **O(n)**：迴圈最多跑 n 次，跟陣列大小成正比，屬於線性時間。
- 對比：插入在陣列**最後面**（且還有空間）不用搬任何東西，是 O(1)。插入位置決定了代價大小。

### 一句話帶走

陣列讀取快是因為連續記憶體，但也因為連續，插入/刪除中間元素要搬動後面所有格子，所以是 O(n)——這是「隨機存取快」的代價。

### 術語表

| 術語 | 定義 |
|---|---|
| Shifting（搬移） | 把陣列裡的元素往前或往後移動一格，通常是為了插入或刪除時保持陣列連續、沒有空隙 |
| In-place（原地） | 直接在原本的記憶體空間裡修改資料，不額外開一塊新陣列 |
| Worst case（最壞情況） | 假設最不利的輸入或位置，估計出來的執行時間上限 |
