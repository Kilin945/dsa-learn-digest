## HashMap / HashSet：O(1) 查找的原理與代價 · 第 3 步

### Load Factor & Resizing

![雜湊表擴容](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_map.assets/hash_table_reshash.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

圖中擴容前，鍵值對 (136, A) 和 (236, D) 落在同一個桶發生衝突；擴容後桶變多，衝突消失。原文道理：雜湊表容量 n 越大，多個 key 被分配到同一個桶的機率越低，衝突越少。

**為什麼需要擴容**
鏈結法下查找成本是 O(1 + 鏈長)。桶數固定、資料持續增加，鏈會越來越長，所以桶數必須跟著資料量成長。

**什麼時候擴容：負載因子**
load factor（負載因子）＝ 元素個數 ÷ 桶數。Java HashMap 預設 16 個桶、負載因子上限 0.75，門檻是 12 筆，放入第 13 筆時擴容為 32 桶，之後依此翻倍。

**擴容怎麼做、代價**
建立兩倍大的新陣列，把每一筆舊資料重新計算索引再放入（rehash）。單次擴容 O(n)；因為每次翻倍，搬動總次數不超過資料筆數的兩倍，攤銷（amortized）後每次 put 仍是 O(1)。

> ⚠ 擴容不是把陣列拉長就好：索引 = 雜湊值 % 容量，容量變了索引就變，所有資料都要重算位置。

```java
void resize() {
    Node[] old = table;
    // 新陣列是舊的兩倍大
    table = new Node[old.length * 2];
    size = 0;
    for (Node head : old) {
        for (Node p = head; p != null;
             p = p.next) {
            // 容量變了，索引要重算
            put(p.key, p.value);
        }
    }
}
```

### 這東西用在哪
- 寫程式：已知資料量時預留容量（約 筆數 ÷ 0.75），Java 19+ 可用 HashMap.newHashMap(n)，省掉多輪 O(n) 搬家與瞬間的記憶體加倍。
- 產品端：用代號快速查東西的功能多半是雜湊表；平均不隨資料量變慢，但記憶體會增加，偶發的搬家停頓會隨資料變多而更明顯；資料到千萬級以上要討論資料庫或外部快取。

### LeetCode · [#217 Contains Duplicate](https://leetcode.com/problems/contains-duplicate/)（Easy）

**題目在說什麼**：陣列裡有任何數字出現兩次以上就回傳 true，否則 false。

**怎麼用今天學的東西解**
1. 準備 HashSet seen 記錄看過的數字。
2. 走訪陣列，對每個 x 呼叫 seen.add(x)。
3. add 回傳 false 代表已存在，直接回傳 true。
4. 走完沒重複回傳 false。

**複雜度**：時間 O(n)，每次 add 平均 O(1)（含擴容攤銷）；空間 O(n)，最壞全部不重複都要存。

```java
public boolean containsDuplicate(
        int[] nums) {
    Set<Integer> seen = new HashSet<>();
    for (int x : nums) {
        // add 回傳 false 代表已存在
        if (!seen.add(x)) return true;
    }
    return false;
}
```

### 術語表
- **Capacity（容量）**：桶的總數，Java HashMap 預設 16。
- **Load Factor（負載因子）**：元素個數 ÷ 桶數，Java 預設上限 0.75。
- **Resize（擴容）**：桶不夠用時換成兩倍大的新陣列。
- **Rehash（重新雜湊）**：擴容後把每筆舊資料重算索引再放入。
- **Amortized（攤銷）**：把偶爾一次的昂貴操作平均分攤到每次操作。
- **HashSet（雜湊集合）**：只存 key 不存 value 的雜湊表，用來判斷有沒有出現過。
