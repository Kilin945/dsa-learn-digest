## 鏈結串列的指標技巧：快慢指標找中點與判環、反轉串列 · 第 3 步

### 概念：Reverse a Singly Linked List

反轉串列的本質，是把每個節點的 `next` 箭頭方向倒過來——原本指向下一個，改成指向前一個。但只要一改 `curr.next`，原本連到後面的路徑就斷了，所以動手改之前一定要先把「還沒改之前的下一個節點」記下來。

用三根指標分工：
- `prev`：已經反轉完成的那一段的新頭
- `curr`：現在正在處理的節點
- `next`：暫存，先接住 curr 原本指向的下一個節點

每一輪迴圈做四件事：存 next → 改 curr.next 指向 prev → prev 推進到 curr → curr 推進到 next。迴圈結束（curr == null）時，prev 就是新的頭節點。

**⚠ 最容易搞錯**：一定要先存 next、再改 curr.next，順序顛倒會讓後面的串列參考永遠遺失、直接斷鏈。

至此三個指標技巧都學完：找中點（快慢指標同時出發）、判環（同一組快慢指標換終止條件）、反轉串列（prev/curr/next 三指標）。三者的共通核心：不靠額外的陣列或雜湊表，只靠幾根指標移動，O(n) 時間、O(1) 空間解決問題。

```java
public ListNode reverseList(ListNode head) {
    ListNode prev = null;
    ListNode curr = head;
    while (curr != null) {
        ListNode next = curr.next; // 先記住下一個節點
        curr.next = prev;          // 反轉箭頭方向
        prev = curr;
        curr = next;
    }
    return prev;
}
```

### 這東西用在哪

- **對工程師**：反轉常被當成回文判斷、需要「反著走」場合的子步驟；原地（in-place）操作，O(1) 額外空間；漏存 next 會導致難以追蹤的斷鏈與 NPE。
- **對產品端**：功能是「復原／倒序顯示」且資料是逐筆串起來時，背後常是這種反轉；操作本身是線性時間，資料量變大不會突然變慢，若真的變慢通常是別處（如重新載入資料）的問題。

### LeetCode 練習

[#206 Reverse Linked List](https://leetcode.com/problems/reverse-linked-list/)（Easy）

把整個單向鏈結串列的方向反過來，回傳新的頭節點。

解法：prev=null、curr=head 起手，迴圈跑到 curr==null，每輪存 next、改 curr.next=prev、prev 與 curr 各自推進；結束後回傳 prev。

複雜度：時間 O(n)（每個節點只走訪一次），空間 O(1)（只用三個變數）。

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        ListNode curr = head;
        while (curr != null) {
            ListNode next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }
        return prev;
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| prev（前一個） | 目前已反轉完成那一段的新頭節點 |
| curr（目前） | 迴圈中正在處理、準備反轉方向的節點 |
| next（下一個） | 暫存用，先接住 curr 原本的下一個節點 |
| in-place（原地操作） | 不額外建立新串列或陣列，直接調整指標完成任務 |
