## 陣列 Array 與動態陣列 ArrayList：連續記憶體的代價與好處 · 第 3 步

### 今日小步：Dynamic Array Resizing: The Doubling Trick

Java 的 ArrayList 底層仍然是普通陣列。它內部維護兩個數字：
- **capacity（容量）**：底層陣列實際配置的格子數。
- **size（目前元素數）**：你實際放入的元素個數，永遠 ≤ capacity。

只要 `size < capacity`，`add()` 只是把新元素放進下一個空格，O(1)。
一旦 `size == capacity`（滿了），就觸發 **resize（搬家）**：配置一個容量兩倍大的新陣列，把舊資料整個複製過去，這一步是 O(n)。

**為什麼 add() 整體算 amortized O(1)？**
因為容量每次翻倍，搬家次數只有 O(log n) 次，且每次搬家成本跟當時已存元素數成正比，把所有搬家成本加總仍是 O(n)。除以 n 次 add，平均攤還成本就是 O(1)。

### 程式碼：手刻一個簡易 DynamicArray

```java
public class DynamicArray {
    private int[] data;
    private int size = 0; // 目前實際放了幾個元素

    public DynamicArray() {
        data = new int[2]; // 初始容量故意設很小，容易看到 resize
    }

    public void add(int value) {
        if (size == data.length) { // size 追上 capacity，滿了
            grow(); // 觸發搬家
        }
        data[size] = value;
        size++;
    }

    private void grow() {
        int[] bigger = new int[data.length * 2]; // 容量翻倍
        for (int i = 0; i < data.length; i++) {
            bigger[i] = data[i]; // 把舊資料整個複製過去，這一步是 O(n)
        }
        data = bigger; // 丟掉舊陣列，改用新陣列
    }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Dynamic Array 動態陣列 | 表面上感覺可以一直新增元素的陣列，底層其實還是普通陣列，滿了就換一個更大的。 |
| Capacity 容量 | 底層陣列實際配置的格子數，通常比目前存的元素數量還多。 |
| Size 目前元素數 | 實際放入、看得到的元素個數，永遠 ≤ capacity。 |
| Resize / Grow 搬家 | 容量不夠時，配置更大的新陣列並把舊資料整個複製過去。 |
| Amortized Time 攤還複雜度 | 把少數幾次昂貴操作的成本平均分攤到很多次便宜操作上，算出的平均複雜度。 |
