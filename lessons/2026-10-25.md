## 雜湊函式與負載因子：hashCode、擴容與 rehash · 第 5 步

### Treeify：單一桶過長時，串列變紅黑樹

![雜湊衝突的最佳情況與最差情況](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_algorithm.assets/hash_collision_best_worst_condition.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

開放定址與鏈式位址都只保證衝突發生時雜湊表還能正常工作，沒辦法減少衝突發生。理想情況（最佳情況）鍵值對均勻分佈在各個桶中，查詢效率最好；最差情況所有鍵值對都存進同一個桶，時間複雜度退化成 O(n)。

**問題：衝突擋不掉。** hashCode 寫得差，或有人刻意送 hashCode 相同的 key，都會讓某個桶被擠爆。桶裡是串列，串列長到 n，查一次要走 n 步，O(n)。

**Java 8 的解法。** 同一桶的串列長度到 8，且桶總數至少 64，就把該桶改成紅黑樹（red-black tree，自動保持平衡的二元搜尋樹）。平衡樹高度約 log₂ n，所以查找是 O(log n)；一萬個元素擠同一桶，串列最多一萬步，樹約 14 步。

**兩個門檻。** 桶數不到 64 時不樹化，而是先擴容（小表的衝突多半只是桶太少）。樹縮到 6 個以下會退回串列；進 8、退 6 留出差距，避免在邊界來回切換。

**為什麼是 8。** hashCode 分散良好時，同一桶長到 8 的機率約一億分之六（JDK 原始碼註解的估算），所以樹化是保險，不是常態。

**⚠ 最容易搞錯。** 樹化不保證一定 O(log n)。樹先比 hash，hash 相同時要靠 key 實作 Comparable 才能繼續比大小；hash 全相同又不能比較的 key，仍接近 O(n)。

```java
// 兩個不同字串，hashCode 都是 2112
String a = "Aa";
String b = "BB";
System.out.println(a.hashCode());
System.out.println(b.hashCode());
// 都印 2112，但兩者並不相等
System.out.println(a.equals(b));
```

### 這東西用在哪

**對寫程式的人。** 自訂 key 類別的 hashCode 要把有區別力的欄位都算進去，能的話再實作 Comparable 當第二道保險。hashCode 寫成常數又不能比較大小，HashMap 會退化成長串列，每次 get 都是 O(n)，資料量小時看不出來，上線後才突然變慢。

**對產品端的人。** 去重、依編號查詢、快取這類功能背後多半是雜湊表，平常速度與資料量無關。一萬筆資料：均勻散開約 1 步，全擠同一桶最壞 1 萬步，有樹化保護約 14 步。雜湊表變慢通常是資料分佈不均，不是資料變多。資安面向是雜湊洪水攻擊（hash flooding）：攻擊者用 Aa、BB 這類 hashCode 相同的字串拼出大量 key，逼服務把它們全擠同一桶；樹化是防線之一。可以問工程師：這個查找最差情況是多少？有人送一堆雜湊值相同的資料進來會不會卡死？

### 動手寫 · LeetCode

[#49 Group Anagrams](https://leetcode.com/problems/group-anagrams/)（Medium）

**題目在說什麼。** 給一堆字串，把字母組成相同、只是排列不同的字串（eat、tea、ate）分到同一組。

**怎麼解。**

1. 把「字母相同」變成一個 key：字元排序後，eat、tea、ate 都變成 aet。
2. HashMap 的 key 是排序後字串，value 是原字串清單。
3. 排序後內容相同的 key，hashCode 一定相同，進同一個桶。
4. 掃過所有字串，用 computeIfAbsent 取得或新建清單並加入原字串。
5. 最後取出所有 value 就是答案。

**複雜度。** 時間 O(N · K log K)：N 個字串各排序一次，HashMap 存取平均 O(1)。空間 O(N · K)：所有字串最後都存在清單裡。

```java
import java.util.*;

class Solution {
    public List<List<String>>
        groupAnagrams(String[] strs) {
        Map<String, List<String>> map =
            new HashMap<>();
        for (String s : strs) {
            char[] cs = s.toCharArray();
            // 排序後字母相同的字串
            // 會得到同一個 key
            Arrays.sort(cs);
            String key = new String(cs);
            map.computeIfAbsent(key,
                k -> new ArrayList<>())
                .add(s);
        }
        return new ArrayList<>(
            map.values());
    }
}
```

### 今日術語表

| 術語 | 中文 | 白話定義 |
|---|---|---|
| Treeify | 樹化 | 同一桶串列太長時改存成樹；Java 8 條件：長度到 8 且桶總數至少 64 |
| Red-black tree | 紅黑樹 | 自動保持平衡的二元搜尋樹，高度約 log₂ n |
| O(log n) | 對數時間 | 資料量翻倍只多一步；一萬筆約 14 步 |
| Comparable | 可比較 | Java 介面，代表物件之間能比大小；樹化時 hash 相同的 key 靠它排順序 |
| Open addressing | 開放定址 | 衝突時桶被佔了就找別的空桶放 |
| Separate chaining | 鏈式位址 | 衝突時同一桶的元素用串列串起來；Java HashMap 採用 |
| Hash flooding | 雜湊洪水攻擊 | 刻意送大量 hashCode 相同的 key，讓雜湊表退化拖垮服務 |
