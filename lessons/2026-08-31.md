## Big-O 複雜度：怎麼估一段程式的快慢 · 第 3 步

### 概念：Time-Space Tradeoff（時間空間互換）

昨天的 Two Sum 暴力解用兩層迴圈，是 O(n²)：外層固定一個數字，內層再掃一次整個陣列找搭檔。

今天的優化：只掃一次陣列，邊掃邊用 **HashMap（雜湊表）** 記下看過的數字。每掃到一個數字，先算出「還缺哪個數字才能湊出 target」（稱為 **complement 補數**），查 HashMap 裡有沒有這個補數：

- 有 → 直接回傳答案
- 沒有 → 把目前的數字存進 HashMap，供之後查詢

HashMap 的查詢／插入平均是 O(1)，所以整體只需一層迴圈，時間變成 **O(n)**。

代價：HashMap 最壞情況要存下所有 n 個數字，所以多花了 **O(n) 的空間（Space Complexity）**。這種「用空間換時間」的取捨，就是 **Time-Space Tradeoff**。

### 程式碼

```java
import java.util.HashMap;

public int[] twoSum(int[] nums, int target) {
    // key: 看過的數字, value: 該數字的索引
    HashMap<Integer, Integer> seen = new HashMap<>();

    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i]; // 我還缺哪個數字
        if (seen.containsKey(complement)) {
            return new int[]{seen.get(complement), i}; // 找到搭檔，直接回傳
        }
        seen.put(nums[i], i); // 記下目前這個數字，給之後的人查
    }
    return new int[]{}; // 找不到
}
```

時間複雜度：O(n)（只掃一次陣列，HashMap 查詢/插入平均 O(1)）
空間複雜度：O(n)（最壞情況 HashMap 存下所有 n 個數字）

### 術語表

- **HashMap（雜湊表）**：key-value 配對的資料結構，查詢平均 O(1)，像已排好索引的電話簿。
- **Complement（補數）**：target 減掉目前這個數字，也就是還缺哪個數字才能湊成答案。
- **Space Complexity（空間複雜度）**：跟 Big-O 一樣的概念，量的是額外記憶體隨 n 成長的速度。
- **Time-Space Tradeoff（時間空間互換）**：用多花的記憶體去換更快的執行時間，或反過來。
