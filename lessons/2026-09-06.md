## 陣列 Array 與動態陣列 ArrayList：連續記憶體的代價與好處 · 第 4 步

### 概念：Array vs ArrayList<Integer> —— 連續記憶體悄悄打折的地方

本主題前三步建立的核心觀念：

1. Array 是連續記憶體（contiguous memory），靠「起始位址 + index × 每格大小」達成 O(1) 隨機存取。
2. 插入/刪除中間元素要搬移（shifting）後面所有元素，是 O(n)——這是隨機存取快的代價。
3. ArrayList 滿了會 resize（配置兩倍大新陣列、複製舊資料），單次 O(n)，但因為容量每次翻倍、搬家次數只有 log n 次，攤還（amortized）下來 add() 平均是 O(1)。

第 4 步（收尾）：**ArrayList<Integer> 其實不是純粹的連續記憶體陣列**。Java 泛型不能放基本型別（primitive type），所以 `ArrayList<Integer>` 底層陣列裡每一格放的是指向 `Integer` 物件的 reference，而非 int 本身——這個轉換叫 autoboxing（自動裝箱）。存取時要多跳一次記憶體，容易造成 cache miss（快取失誤），因此在大量基本型別運算時，`int[]` 通常比 `ArrayList<Integer>` 快、也更省記憶體。

**判斷準則**：已知大小、追求效能、資料是基本型別 → 用 array；大小會變動、需要 collection API（add/remove/contains…）→ 用 ArrayList。

```java
int[] a = new int[5];          // 連續記憶體：5 個 int 緊挨著放
for (int i = 0; i < 5; i++) a[i] = i * i;

List<Integer> b = new ArrayList<>();  // 底層是 Integer[]
for (int i = 0; i < 5; i++) {
    b.add(i * i);   // autoboxing：int 被包成 Integer 物件
                    // b 陣列裡存的是「指向那個物件」的 reference
}
```

### 術語表
- **Autoboxing 自動裝箱**：基本型別自動包成對應物件（int → Integer），才能放進只能裝物件的 collection。
- **Reference 參照／指標**：指向資料實際位置的地址，需多一次跳轉才能取得真正的值。
- **Cache miss 快取失誤**：CPU 想從快取取資料卻不在那，得回頭向較慢的主記憶體要，拖慢效能。
