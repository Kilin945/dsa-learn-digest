## Big-O 複雜度：怎麼估一段程式的快慢 · 第 1 步

### 概念

- **Big-O notation（Big-O 記號）**：用來描述「當輸入資料量 n 變大時，操作次數怎麼成長」，而不是量實際跑幾秒——因為機器速度不同，秒數不能公平比較。
- **O(1)（constant time，常數時間）**：不管 n 多大，操作次數都固定，例如 `arr[0]` 這種索引存取。
- **O(n)（linear time，線性時間）**：操作次數跟 n 成正比，最典型的例子是「把陣列從頭掃到尾一次」。

### 範例：找陣列最大值（O(n)）

```java
int findMax(int[] arr) {
    int max = arr[0];
    // 迴圈跑過整個陣列一次，n 個元素就跑 n 次 → O(n)
    for (int i = 1; i < arr.length; i++) {
        if (arr[i] > max) {
            max = arr[i];
        }
    }
    return max; // 迴圈外的動作只做一次，不影響整體複雜度
}
```

為什麼是 O(n)：迴圈裡的比較動作對 n 個元素各做一次，沒有巢狀迴圈再掃第二次，操作次數跟 n 成正比。

### 術語表

| 術語 | 定義 |
|---|---|
| Big-O notation（Big-O 記號） | 描述操作次數隨輸入資料量成長趨勢的數學記號，例如 O(1)、O(n) |
| time complexity（時間複雜度） | 程式執行所需的基本操作次數，隨輸入資料量變化 |
| input size / n（輸入大小） | 衡量問題規模的變數，例如陣列長度 |
| O(1) constant time（常數時間） | 不管 n 多大，操作次數都固定 |
| O(n) linear time（線性時間） | 操作次數跟 n 成正比，例如掃過整個陣列一次 |
