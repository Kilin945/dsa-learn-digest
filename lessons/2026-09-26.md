## 鏈結串列的指標技巧：快慢指標找中點與判環、反轉串列 · 第 2 步

### Floyd's Cycle Detection（判斷鏈結串列有沒有環）

昨天用 fast/slow 找中點，靠的是「fast 撞到底時 slow 恰好走了一半」。今天要解的問題不一樣：判斷一個鏈結串列裡有沒有「環」（cycle，某個節點的 next 又繞回去指到前面已經走過的節點，形成一個圈，沿著 next 一直走永遠走不到 null）。做法一樣讓 fast 一次走兩步、slow 一次走一步：如果串列真的有環，兩根指標最後一定會在環裡的某一點相遇；如果 fast 能順利走到 null，就代表根本沒有環。

**比喻**：兩個人在跑道上跑步，一快一慢，同一起點出發。封閉的環形跑道（有環）上，快的人繞一圈後會從後面追上慢的人，兩人終究會碰頭；直線跑道、跑到底是終點（沒有環），快的人只會先到終點，永遠不會回頭撞到還在後面的人。

**⚠ 最容易搞錯的地方**：判斷相遇要用 `slow == fast`（比較是不是同一個節點的參考），不能改成比較 `slow.val == fast.val`（比較數值）。串列裡可能有重複的數值，比值的話沒有環也可能被誤判成有環。

```java
public boolean hasCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;
    while (fast != null
        && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            return true;
        }
    }
    return false;
}
```

🥡 一句話帶走：同一組快慢指標，把「fast 撞到底代表 slow 在中點」換成「slow 追上 fast 代表繞了一圈」，就能不多開記憶體地抓出資料裡的死圈。

### 這東西用在哪

**對寫程式的人**：這招在正式程式碼裡通常是拿來防呆——如果某段邏輯不小心把節點的 next 指標接錯、接回前面走過的節點，資料結構就變成繞不出去的環，任何「從頭走到底」的程式都會卡進無窮迴圈。用 Floyd 演算法先檢查一次，只用兩個指標變數、不用額外開 HashSet，資料量大時特別划算。

**對產品端的人**：聽到「這支功能卡住、CPU 飆高、request 一直沒回應」，很多時候背後是資料被寫成環狀結構、程式繞不出來。這種問題平常資料量小時很難被抓到（繞一圈耗時很短、不會被注意），上線後資料變多或觸發某個邊界情況，就會變成看起來整個系統卡死的重大事故。可以問工程師：「會不會是資料結構裡繞出了一個環？」

### 動手寫 · LeetCode

[#141 Linked List Cycle](https://leetcode.com/problems/linked-list-cycle/)（Easy）

**題目**：給頭節點 head，判斷串列裡有沒有環（某節點透過 next 繞回前面走過的節點）。

**解法步驟**：
1. slow、fast 都從 head 出發
2. while 條件：fast != null 且 fast.next != null
3. 每輪 slow 走一步、fast 走兩步
4. 每輪用 == 檢查 slow 和 fast 是否同一節點，是則回傳 true
5. 迴圈跑完（fast 到 null）回傳 false

**複雜度**：時間 O(n)——沒環時 fast 最多走 n/2 輪碰 null，有環時 fast 進環後最多再繞一圈就追上 slow，都不會無窮迴圈。空間 O(1)——只用兩個指標變數，不像 HashSet 解法要開一份跟長度成正比的空間。

```java
public boolean hasCycle(ListNode head) {
    ListNode slow = head;
    ListNode fast = head;
    while (fast != null
        && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {
            return true;
        }
    }
    return false;
}
```

### 今日術語表

- **Cycle（環）**：鏈結串列中某個節點的 next 又繞回去指到前面已經走過的節點，形成一個沿著 next 走不出去的圈。
- **Floyd's Cycle Detection（弗洛伊德判環演算法）**：用快慢指標判斷鏈結串列是否有環的經典解法，也常被叫做「龜兔賽跑演算法」。
- **Reference comparison（參考比較）**：用 == 比較兩個變數是不是指向記憶體中同一個物件，而不是比較物件裡面裝的值是否相同。
