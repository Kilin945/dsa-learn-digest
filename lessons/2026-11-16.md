## 平衡樹 AVL：BST 為什麼會退化、旋轉怎麼救回來 · 第 5 步

### Rebalance: Choosing the Right Rotation in Code

![AVL 樹的四種旋轉情況](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_tree/avl_tree.assets/avltree_rotation_cases.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

原文說四種失衡情況與前面案例逐個對應，分別需要右旋、先左旋後右旋、先右旋後左旋、左旋。看圖時先看 node 往哪邊重，再看較重那側的 child 往哪邊重：同側用單旋轉，反向用雙旋轉。

**為什麼要包成一個函式**：插入或刪除後不知道會遇到哪種失衡，所以把檢查與選招包成 rebalance，每個節點處理完呼叫一次。

**兩層判斷選招**：第一層看 node 的平衡因子（>1 左重、<-1 右重）；第二層看 child 的平衡因子。左重且 child 為負就先左旋 child 再右旋 node；否則直接右旋；右重則鏡像。

**一路往上檢查**：插入用遞迴，回程每層先 updateHeight 再 rebalance。路徑長度是樹高 O(log n)，每層 O(1)，整體 O(log n)。

**注意**：旋轉後要先更新降下來的 node 高度，再更新升上去的 child，順序顛倒高度會是舊值。

```java
int height(TreeNode n) {
    return n == null ? 0 : n.height;
}

int balanceFactor(TreeNode n) {
    int l = height(n.left);
    int r = height(n.right);
    return l - r;
}

void updateHeight(TreeNode n) {
    int l = height(n.left);
    int r = height(n.right);
    n.height = 1 + Math.max(l, r);
}

TreeNode rebalance(TreeNode n) {
    int bf = balanceFactor(n);
    if (bf > 1) {
        // 左重，看 child 是否右重
        if (balanceFactor(n.left) < 0)
            n.left = leftRotate(n.left);
        return rightRotate(n);
    }
    if (bf < -1) {
        // 右重，看 child 是否左重
        if (balanceFactor(n.right) > 0)
            n.right =
                rightRotate(n.right);
        return leftRotate(n);
    }
    return n;
}

TreeNode insert(TreeNode n, int v) {
    if (n == null)
        return new TreeNode(v);
    if (v < n.val)
        n.left = insert(n.left, v);
    else if (v > n.val)
        n.right = insert(n.right, v);
    else
        return n;
    // 回程：先更新高度，再檢查平衡
    updateHeight(n);
    return rebalance(n);
}
```

### 這東西用在哪

- 寫程式的人：要排序又要頻繁增刪時用平衡樹（Java 的 TreeMap/TreeSet 底層是紅黑樹）；用普通 BST 遇到已排序資料會退化成 O(n)。平衡樹買到的是最壞情況的 O(log n) 保證。
- 產品端：「永遠排好序」「快速查範圍」的功能背後常是平衡樹或資料庫索引；資料放大一千倍，查詢步數只從約 10 步變約 20 步。可問工程師：資料量放大一百倍時，耗時只多一點點還是跟著放大一百倍？

### 動手寫 · LeetCode

[#110 Balanced Binary Tree](https://leetcode.com/problems/balanced-binary-tree/)（Easy）

**題目**：判斷二元樹是否平衡——每個節點左右子樹高度差都不超過 1。

**解法步驟**：
1. 寫 height 函式，空節點為 0。
2. 回程中順便算左高減右高。
3. 絕對值大於 1 就回傳 -1 並一路往上傳。
4. 主函式檢查結果是否為 -1。

**複雜度**：時間 O(n)，每個節點只走訪一次；空間 O(h)，遞迴深度等於樹高。

```java
class Solution {
    public boolean isBalanced(
            TreeNode root) {
        return height(root) != -1;
    }

    // 回傳高度；不平衡就回傳 -1
    private int height(TreeNode n) {
        if (n == null) return 0;
        int l = height(n.left);
        // 左邊已不平衡，直接往上傳
        if (l == -1) return -1;
        int r = height(n.right);
        if (r == -1) return -1;
        // 高度差超過 1 就不平衡
        if (Math.abs(l - r) > 1)
            return -1;
        return 1 + Math.max(l, r);
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| rebalance | 再平衡 | 檢查節點是否失衡並挑對旋轉修好的函式 |
| balance factor | 平衡因子 | 左子樹高度減右子樹高度，AVL 要求在 -1 到 1 之間 |
| updateHeight | 更新高度 | 用左右子樹較高者加 1 重算節點高度 |
| recursion | 遞迴 | 函式呼叫自己，往下找位置、回程順便整理 |
| Red-Black tree | 紅黑樹 | 另一種自平衡 BST，Java TreeMap 使用 |
| O(log n) | 對數時間 | 資料放大一倍步數只多約一步 |
