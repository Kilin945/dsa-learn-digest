## Heap / PriorityQueue：完全二元樹、上浮下沉與 Top-K · 第 3 步

### Top-K with a Min-Heap

![基於堆積尋找最大的 k 個元素](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_heap/top_k.assets/top_k_heap_step1.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

流程：
1. 初始化一個小頂堆積，堆積頂元素最小。
2. 先把陣列前 k 個元素依序入堆積。
3. 從第 k+1 個元素開始，若當前元素大於堆積頂，就把堆積頂出堆積、當前元素入堆積。
4. 走訪完成後，堆積中就是最大的 k 個元素。

**為什麼不排序**：排序是 O(n log n)，只要前 k 名卻把全部排序，做太多；走訪 k 輪是 O(nk)，k 接近 n 時退化成 O(n²)。

**門檻比喻**：堆積頂是前 k 名裡最弱的那個，新元素只要和它比，贏了就換、輸了就略過。

**走一遍**（k = 3）：

```
nums = [5, 2, 8, 1, 9, 3], k = 3
前 3 個入堆積 → {2, 5, 8}
1 > 2？否 → 跳過
9 > 2？是 → 2 出、9 入 → {5, 8, 9}
3 > 5？否 → 跳過
答案：{5, 8, 9}
```

**複雜度**：時間 O(n log k)（n 個元素，每個最多一次 O(log k) 的整理，堆積最多 k 個）；空間 O(k)。

**最容易搞錯**：找「最大的 k 個」用小頂堆積，找「最小的 k 個」才用大頂堆積。

### 這東西用在哪

- 工程師：熱門前 N 名、頻率最高的 K 個關鍵字、串流資料。堆積只需 O(k) 記憶體，排序要存全部。k 接近 n 時直接排序更簡單。
- 產品端：排行榜類功能多半是維護前 k 名的小名單；資料變多時時間約成比例增加，與前幾名的 k 關係不大。若需求變成「每個人都要知道名次」就是完整排序，成本不同。

### 動手寫 · LeetCode [#215 Kth Largest Element in an Array](https://leetcode.com/problems/kth-largest-element-in-an-array/)（Medium）

**題目在說什麼**：給未排序整數陣列與 k，回傳排序後第 k 大的數字（重複值照算）。

**解法步驟**：
1. 建小頂堆積（PriorityQueue 預設）。
2. 每個數字 offer 進堆積。
3. 大小超過 k 就 poll 掉最小的。
4. 最後 peek 即第 k 大。

**複雜度**：時間 O(n log k)，空間 O(k)。

```java
import java.util.PriorityQueue;

class Solution {
    public int findKthLargest(
            int[] nums, int k) {
        // 小頂堆積，最多放 k 個
        PriorityQueue<Integer> heap =
            new PriorityQueue<>();
        for (int num : nums) {
            heap.offer(num);
            // 超過 k 個就踢掉最小的
            if (heap.size() > k) {
                heap.poll();
            }
        }
        // 堆積頂就是第 k 大
        return heap.peek();
    }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Top-K | 前 k 名問題 | 從資料中找出最大（或最小）的 k 個 |
| Min Heap | 小頂堆積 | 堆積頂是最小值，今天當作前 k 名的門檻 |
| peek | 偷看堆積頂 | 只看不取，O(1) |
| Stream | 資料串流 | 資料陸續進來，無法一次載入 |
| O(n log k) | n 乘 log k | n 個元素各花 log k 整理 |
