## Queue 佇列與 Deque：先進先出、環形佇列與雙端佇列 · 第 1 步

### Queue: First In, First Out (FIFO)

![佇列的先入先出規則](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_stack_and_queue/queue.assets/queue_operations.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

佇列（queue）像排隊：新來的人加入隊伍尾部，隊伍頭部的人逐個離開。頭部叫「佇列首」，尾部叫「佇列尾」，加入列尾叫「入列」，刪除佇列首元素叫「出列」。資料從佇列尾進、從佇列首出，這就是先入先出（FIFO）。

**先用排隊來理解**：佇列只准動兩個位置，最後面加人、最前面拿人。

**三個基本動作**：入列 offer、出列 poll、偷看 peek。三者只碰最前或最後一個位置，所以都是 O(1)。

**和堆疊對照**：堆疊後進先出、進出同一端；佇列先進先出、進出不同端。堆疊處理最新的，佇列處理最舊的。

> ⚠ 最容易搞錯：poll()/peek() 遇空佇列回傳 null，remove()/element() 遇空佇列丟例外；offer() 失敗回傳 false，add() 失敗丟例外。建議固定用 offer/poll/peek 並先檢查 isEmpty()。

```java
Queue<String> q = new ArrayDeque<>();
// 入列：依序站到隊伍最後面
q.offer("A");
q.offer("B");
q.offer("C");
// 偷看隊首是誰，不拿走
q.peek();
// 出列：隊首離開，x 拿到 A
String x = q.poll();
// 現在隊伍剩 B、C，B 在最前面
```

一句話：佇列是先進先出，從尾巴進、從頭出，入列出列都是 O(1)。

### 這東西用在哪

**對寫程式的人**：BFS、背景工作排程、訊息佇列、滑動視窗都用佇列。順序由結構保證，少寫索引管理。Java 建議用 ArrayDeque；拿 ArrayList 當佇列，每次從最前面刪除要搬動後面所有元素，變成 O(n)。

**對產品端的人**：客服排隊、訂單處理、列印工作、候補名單這類先來先服務的功能背後多半是佇列。隊伍多長，叫下一位都一樣快；真正的風險是到達速度大於處理速度時隊伍會無限積壓。一般佇列沒有插隊或優先級。

### 動手寫 · LeetCode

[#933 Number of Recent Calls](https://leetcode.com/problems/number-of-recent-calls/)（Easy）

**題目在說什麼**：每次請求進來給時間 t（遞增），回答 [t-3000, t] 內共有幾個請求。

**怎麼用佇列解**：
1. 請求按時間順序進來，最舊的在最前面。
2. 新請求 offer(t) 入列。
3. peek() 看佇列首，若小於 t-3000 代表過期。
4. 過期就 poll() 出列，重複到佇列首在視窗內。
5. size() 就是答案。

**複雜度**：時間 O(1) 攤銷，每個請求入列一次、出列最多一次；空間 O(W)，只留視窗內的請求。

```java
import java.util.*;

class RecentCounter {
    private Queue<Integer> q =
        new ArrayDeque<>();

    public int ping(int t) {
        // 新請求從佇列尾進來
        q.offer(t);
        // 隊首已超出 3000ms 就出列
        while (q.peek() < t - 3000) {
            q.poll();
        }
        // 剩下的都在視窗內
        return q.size();
    }
}
```

### 術語表

| 術語 | 中文 | 說明 |
|---|---|---|
| Queue | 佇列 | 從尾端加入、從前端取出的資料結構 |
| FIFO | 先入先出 | 先進來的先被取出 |
| front / rear | 佇列首／佇列尾 | 隊伍最前面與最後面 |
| enqueue / offer | 入列 | 加到佇列尾 |
| dequeue / poll | 出列 | 拿掉佇列首並回傳 |
| peek | 偷看 | 只看佇列首，不拿走 |
| Exception | 例外 | 執行中遇到錯誤而中斷的機制 |
