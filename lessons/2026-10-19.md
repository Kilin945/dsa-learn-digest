## HashMap / HashSet：O(1) 查找的原理與代價 · 第 11 步

### What makes a good hash function? (String.hashCode)

![雜湊衝突示例](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_map.assets/hash_collision.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

圖中的雜湊函式只取學號後兩位，學號 12836 和 20336 後兩位都是 36，被算到同一個位置，指向同一個姓名。原文指出輸入空間通常遠大於輸出空間，所以雜湊衝突一定會發生；好的函式能讓衝突分散。

**好函式的三個要求**

1. 確定性（deterministic）：同一個 key 每次結果都相同。
2. 要快：每次 put、get 都要先算一次。
3. 均勻分佈（uniform distribution）：不同 key 平均落在各桶，這一項最難也最影響效能。

**Java 怎麼算字串的 hashCode**

從 h = 0 開始，每讀一個字元就 h = 31 × h + 字元。每個字元都參與，且位置不同權重不同。String 會快取算過的值。

**為什麼不是單純加總**

只加總的話 abc 與 cba 會撞在一起。乘質數 31 讓順序有影響；31 是奇數質數，且 31×h 等於 (h << 5) - h，運算快。

> ⚠ hashCode 相同不代表是同一個 key。"Aa" 與 "BB" 的 hashCode 都是 2112。雜湊函式只決定放哪個桶，是否同一個 key 由 equals 決定；equals 相等則 hashCode 必須相等。

```java
// 概念上 hashCode 是這樣算的
int h = 0;
for (char c : s.toCharArray()) {
  h = 31 * h + c;
}

// 兩個不同字串，hashCode 相同
"Aa".hashCode();
"BB".hashCode();
```

### 這東西用在哪

**對寫程式的人**：內建型別的 hashCode 已寫好；自訂 key 要納入所有區分身分的欄位（可用 Objects.hash）。hashCode 寫成常數雖合法，但所有資料進同一桶，HashMap 退化成鏈結串列，查找 O(n)，且不會報錯。

**對產品端的人**：即時查重、輸入編號立刻帶出資料多半是雜湊表。key 太集中（例如只有最後幾碼不同）時，資料少時很快，放大到幾百萬筆可能突然變慢。資安上有 hash flooding：攻擊者故意送雜湊值相同的 key 拖慢伺服器，所以現代語言加了保護（如 Java 8 樹化）。可問工程師：拿什麼當 key？分佈夠散嗎？

### LeetCode：[#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

**題目**：不用內建 HashMap，自己實作 put、get（找不到回 -1）、remove，key 與 value 皆為整數。

**解法步驟**

1. 長度 769 的陣列，每格是一個串列（鏈結法）。
2. hash(key) = key % 769 決定桶。
3. put：桶內找到相同 key 就更新，否則新增。
4. get：桶內逐筆比對，找不到回 -1。
5. remove：桶內移除相同 key 的那筆。

**複雜度**：時間平均 O(1)、最壞 O(n)，因為每次只掃一個桶；空間 O(769 + n)，陣列固定加上每筆資料一個節點。

```java
import java.util.LinkedList;

class MyHashMap {
  private static final int SIZE = 769;
  private LinkedList<int[]>[] buckets;

  public MyHashMap() {
    buckets = new LinkedList[SIZE];
    for (int i = 0; i < SIZE; i++) {
      buckets[i] = new LinkedList<>();
    }
  }

  // 雜湊函式：key 對 769 取模
  private int hash(int key) {
    return key % SIZE;
  }

  public void put(int key, int value) {
    LinkedList<int[]> b =
        buckets[hash(key)];
    for (int[] p : b) {
      // 已有這個 key，更新後結束
      if (p[0] == key) {
        p[1] = value;
        return;
      }
    }
    // 桶裡沒有，新增一筆
    b.add(new int[]{key, value});
  }

  public int get(int key) {
    for (int[] p : buckets[hash(key)]) {
      if (p[0] == key) return p[1];
    }
    return -1;
  }

  public void remove(int key) {
    buckets[hash(key)].removeIf(
        p -> p[0] == key);
  }
}
```

### 術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| deterministic | 確定性 | 同一個輸入每次算出來都一樣 |
| uniform distribution | 均勻分佈 | 不同 key 平均落在各桶 |
| String.hashCode() | 字串雜湊值 | h = 31 × h + 字元 的累積規則 |
| hash flooding | 雜湊洪水攻擊 | 故意送雜湊值相同的 key 讓雜湊表變慢 |
