## Big-O 複雜度：怎麼估一段程式的快慢 · 第 5 步

### O(log n): Logarithmic Time（對數時間）

**核心概念**

在已排序的資料中，每次都檢查「範圍正中間」的值，並依大小關係丟掉一半的搜尋範圍，這種技巧叫 **Binary Search（二分搜尋）**。因為範圍每次都砍半：n → n/2 → n/4 → ... → 1，跑的次數 k 滿足 n / 2^k = 1，解出 k = log₂(n)，所以操作次數跟 log n 成正比，這就是 **O(log n)**。

前提：資料必須先排序好，否則無法判斷該往左找還是往右找。

**程式碼（Java）**

```java
// 前提：arr 必須已經排序好
int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2; // 取中間索引，避免相加溢位
        if (arr[mid] == target) {
            return mid;               // 剛好猜中
        } else if (arr[mid] < target) {
            lo = mid + 1;             // 目標比中間大 -> 丟掉左半邊
        } else {
            hi = mid - 1;             // 目標比中間小 -> 丟掉右半邊
        }
    }
    return -1; // 找不到
}
```

**複雜度家族總結（本主題收尾）**

O(1) < O(log n) < O(n) < O(n log n) < O(n²)

（O(n log n) 會在之後講排序演算法時詳細說明。）
