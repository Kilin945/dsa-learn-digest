## HashMap / HashSet：O(1) 查找的原理與代價 · 第 9 步

### Bucket Index: Why Capacity Is a Power of 2

![雜湊函式工作原理](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_map.assets/hash_function.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

雜湊函式分兩步：先用 hash() 算出雜湊值，再對桶數量 capacity 取模得到桶的編號 index。原文例子是 capacity = 100、hash(key) = key，函式即 key % 100。Java 的 HashMap 把第二步的取模換成位元 AND。

**第二步其實不用 %**：Java 用 `h & (n - 1)` 代替 `h % n`。位元 AND 是兩邊同位都是 1 才得 1。

**為什麼結果一樣**：n = 16 時 n - 1 = 15 = 0b1111，AND 之後只留最後 4 位，等於除以 16 的餘數。只要容量是 2 的次方，`h & (n - 1)` 與 `h % n` 完全相同，且不會像 % 在 hashCode 為負時算出負索引。

```java
n = 16, n - 1 = 15 = 0b1111
h = 37 = 0b100101

// 只留最後 4 位 0101
h & 15 = 0b0101 = 5
// 餘數也是 5
37 % 16 = 5
```

**只看低位的副作用與補救**：高位被忽略，例如 0x00010000 與 0x00020000 在 n = 16 時都落在桶 0。Java 先做擴散 `h ^ (h >>> 16)`，兩者變成 0x00010001、0x00020002，桶位分別是 1 與 2。

```java
int h = key.hashCode();
// 高 16 位混進低 16 位
h = h ^ (h >>> 16);
// n 是 2 的次方，等同 h % n
int index = h & (n - 1);
```

**所以容量一定是 2 的次方**：`new HashMap<>(100)` 實際會補成 128；擴容翻倍剛好維持 2 的次方。

> ⚠ 最容易搞錯：`& (n - 1)` 等於 `% n` 只在 n 是 2 的次方時成立。容量取 1000 配 `& 999`（0b1111100111），1000 個桶只有 256 個會被用到。

### 這東西用在哪

**對寫程式的人**：預留容量時實際桶數是不小於該數的最小 2 的次方；預計放 1000 筆要給約 1334 以上才不會擴容（負載因子 0.75）。自己實作雜湊表時容量或遮罩選錯，會悄悄退化成慢查找。

**對產品端的人**：雜湊表像固定格數的信箱牆，格數刻意取 2 的次方讓算格子最快。資料平均分散時，十筆和一千萬筆的單次查找一樣快；會變慢的通常是資料分配不均，或擴容時全部資料重新搬家的那一瞬間。可問工程師：「這個查找變慢是資料量造成，還是分配不均造成？擴容時會不會卡住？」

### 動手寫 · LeetCode

[#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

題目：不用內建 HashMap，自己實作 put、get（沒有回傳 -1）、remove。

解法步驟：
1. 開長度 1024 的陣列，每格是鏈結串列當桶。
2. 桶位 = `(key ^ (key >>> 16)) & 1023`。
3. put：掃桶，key 存在就更新，否則新增。
4. get：掃桶，找到回傳 value，否則 -1。
5. remove：刪掉桶中 key 相同的那筆。

複雜度：時間 O(n / 1024)，約等於 O(1)（桶數固定，鏈長 = 資料量 ÷ 1024）；空間 O(1024 + n)。

```java
import java.util.*;

class MyHashMap {
  static final int N = 1024;
  // 每個桶是一串 {key, value}
  LinkedList<int[]>[] t;

  public MyHashMap() {
    t = new LinkedList[N];
    for (int i = 0; i < N; i++)
      t[i] = new LinkedList<>();
  }

  // 高位混進低位，再用 & 取桶
  int idx(int key) {
    int h = key ^ (key >>> 16);
    return h & (N - 1);
  }

  public void put(int key, int value) {
    for (int[] e : t[idx(key)]) {
      if (e[0] == key) {
        // key 已存在，更新
        e[1] = value;
        return;
      }
    }
    int[] p = {key, value};
    t[idx(key)].add(p);
  }

  public int get(int key) {
    for (int[] e : t[idx(key)]) {
      if (e[0] == key) return e[1];
    }
    return -1;
  }

  public void remove(int key) {
    var b = t[idx(key)];
    b.removeIf(e -> e[0] == key);
  }
}
```

### 術語表

| 術語 | 中文 | 白話定義 |
|---|---|---|
| bit | 位元 | 電腦存數字的最小單位，0 或 1 |
| AND (&) | 位元 AND | 同位兩邊都是 1 才得 1 |
| XOR (^) | 互斥或 | 相同得 0、不同得 1 |
| >>> | 無號右移 | 整串位元往右推，左邊補 0 |
| power of 2 | 2 的次方 | 1、2、4、8、16…，二進位只有一個 1 |
| spread | 擴散 | 把高位混進低位，讓高位差異影響桶位 |
| capacity | 容量 | 桶數，即底層陣列長度 |
