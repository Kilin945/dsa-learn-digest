## 雜湊衝突：鏈結法 chaining 與開放定址 open addressing · 第 5 步

### Chaining vs Open Addressing: The Trade-offs

兩種解衝突的做法沒有誰贏，只有各自划算的情境。

![鏈式位址雜湊表](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_collision.assets/hash_table_chaining.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

鏈式位址把每個桶換成鏈結串列，所有發生衝突的鍵值對都儲存在同一條串列中，衝突資料掛在桶外。

![開放定址（線性探查）雜湊表的鍵值對分佈](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_collision.assets/hash_table_linear_probing.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

開放定址（線性探查）遇到衝突就往後找空桶，最後兩位相同的 key 依序住在該桶與其下的桶；查詢遇到空桶代表不存在。

**核心差別**：衝突的資料放桶外（串列節點）還是桶內（陣列其他格子）。

**刪除與擁擠程度**：鏈結法直接拆節點；開放定址要放墓碑。鏈結法負載因子可超過 1；開放定址筆數最多等於桶數，接近滿時聚集使探查變慢，擴容門檻要更保守。

**記憶體**：鏈結法每筆多一個節點與指標，節點散落；開放定址資料連續，對 CPU 快取友善。

**實際選擇**：Java HashMap 用鏈結法加樹化；ThreadLocalMap 用線性探查。

> ⚠ 開放定址的負載因子不能超過 1，且遠在 1 之前就會明顯變慢，不要把 0.75 這類門檻直接互相套用。

### 這東西用在哪

**對寫程式的人**：日常用 HashMap 即可；自己寫固定大小小型快取或讀到線性探查的程式時，要想到墓碑與提早擴容。面試常考手寫雜湊表。

**對產品端的人**：秒查功能（會員編號查詢、重複檢查、快取）背後多半是雜湊表，資料量變大查詢速度通常不變；會變慢的是擴容那一次的偶發卡頓，以及 key 分布太偏的時候。可問工程師：「擴容時會不會卡一下？key 分布夠平均嗎？」

### LeetCode · [#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

**題目**：不用內建 HashMap，自己做出 put、get（沒有回 -1）、remove。

**解法步驟**：
1. 準備 769 個桶，每個桶一條串列（鏈結法）。
2. 桶號 = key % 769。
3. put：走訪串列，有相同 key 就覆蓋，沒有就接新節點。
4. get：走訪串列，找到回值，沒找到回 -1。
5. remove：直接拆節點，不需要墓碑。

**複雜度**：時間 O(n / 769) ≈ O(1)，因為只走一條串列，平均長度是筆數除以 769；空間 O(n + 769)，每筆一個節點加固定桶數。

```java
import java.util.*;

class MyHashMap {
    private static final int SIZE = 769;
    private List<int[]>[] b;

    public MyHashMap() {
        b = new List[SIZE];
        // 每個桶放一條空串列
        for (int i = 0; i < SIZE; i++) {
            b[i] = new LinkedList<>();
        }
    }

    // 依 key 找到它所在的那條串列
    private List<int[]> chain(int k) {
        return b[k % SIZE];
    }

    public void put(int key, int val) {
        for (int[] e : chain(key)) {
            if (e[0] == key) {
                // 已有相同 key 就覆蓋
                e[1] = val;
                return;
            }
        }
        // 沒找到就接上新節點
        chain(key).add(
            new int[]{key, val});
    }

    public int get(int key) {
        for (int[] e : chain(key)) {
            if (e[0] == key) {
                return e[1];
            }
        }
        return -1;
    }

    public void remove(int key) {
        // 直接拆節點，不需要墓碑
        chain(key).removeIf(
            e -> e[0] == key);
    }
}
```

### 術語表

- **Separate chaining（鏈式位址）**：每個桶接一條鏈結串列，衝突資料掛在同一條串列。
- **Open addressing（開放定址）**：衝突時在陣列裡另找空桶，資料都住在桶裡。
- **Linear probing（線性探查）**：衝突時固定一格一格往後找空桶。
- **Tombstone（墓碑）**：開放定址刪除時留下的記號，查詢不可在此停下。
- **Load factor（負載因子）**：筆數 ÷ 桶數。
- **Cache（快取）**：離 CPU 很近的小而快的記憶體。
- **Pointer（指標）**：記錄下一個東西放在記憶體哪裡的欄位。
