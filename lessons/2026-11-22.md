## 樹的經典題型：深度、直徑、最近共同祖先 LCA · 第 4 步

### Wrap-up: One Post-order Template for Three Problems

**三題回頭看，長得一樣**：最大深度、直徑、LCA 都用後序走訪（postorder，先處理左右子樹，最後處理自己），先拿到左右結果，再決定自己做什麼。

**差別只在兩件事**：(1) 回傳給父節點什麼？(2) 要不要順手更新全域答案？
- 深度：回傳高度，無全域答案。
- 直徑：回傳單邊高度，全域答案記左加右。
- LCA：回傳「這棵子樹有找到誰」，左右都找到時當前節點就是答案。

**通用骨架**：時間 O(n)（每個節點造訪一次），空間 O(h)（遞迴堆疊最深為樹高）。

```java
int ans = 0;

int dfs(TreeNode node) {
    if (node == null) return 0;
    int l = dfs(node.left);
    int r = dfs(node.right);
    // 用左右結果更新全域答案
    ans = Math.max(ans, l + r);
    // 只回傳單邊高度給父節點
    return 1 + Math.max(l, r);
}
```

> ⚠ 最容易搞錯：回傳給父節點的值和最後要的答案常常不是同一個東西。直徑若回傳左加右，父節點會重複計算兩條分支。

### 這東西用在哪

**對寫程式的人**：目錄總大小、組織架構最深層級、巢狀 JSON 驗證、權限繼承找共同上層。遞迴加回傳摘要，不用先攤平再重算。樹極深時遞迴會 StackOverflowError，需改迭代或限制深度。

**對產品端的人**：組織圖層數、資料夾總容量、共同主管這類功能背後多半是在樹上走一遍。工作量與節點數成正比，一千變一千萬是慢十倍而不是突然垮掉；若每次都重算整棵樹，可問工程師結果有沒有快取。

### 動手寫 · LeetCode

[#110 Balanced Binary Tree](https://leetcode.com/problems/balanced-binary-tree/)（Easy）

**題目在說什麼**：判斷二元樹是否平衡——每個節點左右子樹高度差不超過 1。

**怎麼用今天學的東西解**：
1. 後序走訪，先拿左右高度再判斷自己。
2. 回傳值是高度，空節點為 0。
3. 高度差大於 1 就回傳 -1。
4. 任一邊回傳 -1 就一路往上傳 -1。
5. 根節點回傳值不是 -1 就是平衡。

**複雜度**：時間 O(n)，每個節點最多造訪一次；空間 O(h)，遞迴堆疊深度為樹高。

```java
class Solution {
    public boolean isBalanced(
            TreeNode root) {
        return height(root) != -1;
    }

    // 回傳高度；不平衡就回傳 -1
    private int height(TreeNode node) {
        if (node == null) return 0;
        int l = height(node.left);
        if (l == -1) return -1;
        int r = height(node.right);
        if (r == -1) return -1;
        // 高度差超過 1 就不平衡
        if (Math.abs(l - r) > 1)
            return -1;
        return 1 + Math.max(l, r);
    }
}
```

### 今日術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Postorder | 後序走訪 | 先處理左右子樹，最後處理自己 |
| Return value | 回傳值 | 遞迴函式交給父節點的結果，不一定等於最終答案 |
| Global answer | 全域答案 | 函式外、每個節點都能更新的變數 |
| Balanced tree | 平衡樹 | 每個節點左右高度差不超過 1 |
| Sentinel value | 哨兵值 | 用不可能是正常結果的值（如 -1）代表特殊狀態 |
