## 陣列上的掃描技巧：雙指標、滑動視窗、前綴和 · 第 2 步

### 今日概念：Sliding Window（滑動視窗）

昨天的雙指標是從陣列兩端各站一個指標，相向靠近；今天的滑動視窗換一種站法——兩根指標都從左邊出發、都只往右走，中間夾住的一段叫做「視窗」（window）。右指標負責把新元素收進視窗（視窗變大），左指標負責在條件不滿足時把最左邊的元素移出視窗（視窗變小）。

因為兩根指標各自只往右走、不會回頭，每個元素最多被加進視窗一次、移出視窗一次，所以整體是 O(n)，比暴力解「每個起點都重新掃一次」的 O(n²) 快得多。

⚠ 容易搞混：雙指標是相向而行（一左一右往中間靠），滑動視窗是同向而行（兩根都往右走，左指標走得比較慢）。

滑動視窗骨架：

```java
int l = 0, sum = 0;
for (int r = 0; r < n; r++) {
    sum += nums[r];
    // 條件不滿足就收縮左邊界
    while (needShrink) {
        sum -= nums[l];
        l++;
    }
}
```

### 這東西用在哪

- **對工程師**：題目要在陣列/字串裡找「某段連續區間」滿足某個條件，且視窗移動一格只需加一個減一個即可更新答案時，就該用滑動視窗；用錯的情況是題目要的不是連續區間（任意挑選組合），硬套只會讓程式碼變複雜。
- **對產品端**：看到「找一段連續時間/資料裡最符合某條件的區間」這類功能，背後常是滑動視窗，計算量只跟資料筆數成正比，資料變大也不會爆炸性變慢；若工程師說條件不連續、滑動視窗用不上，複雜度可能較差，工時要多抓。

### LeetCode 練習

[#209 Minimum Size Subarray Sum](https://leetcode.com/problems/minimum-size-subarray-sum/)（Medium）

給一個正整數陣列與目標值 target，找出「總和至少是 target」的最短連續子陣列長度，找不到回傳 0。

解法步驟：
1. left、right 兩指標圈出視窗，right 往右擴大視窗並累加 sum。
2. sum 達到 target 就記錄目前視窗長度是否為最短。
3. 視窗已達標就把 left 右移縮小視窗、sum 扣掉移出的元素，重複到不再達標。
4. right 走到底後回傳記錄的最短長度。

複雜度：時間 O(n)（left、right 各自只往右走，總共最多 2n 步）；空間 O(1)（只用常數個額外變數）。

```java
class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int left = 0, sum = 0, best = Integer.MAX_VALUE;
        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum >= target) {
                best = Math.min(best, right - left + 1);
                sum -= nums[left];
                left++;
            }
        }
        return best == Integer.MAX_VALUE ? 0 : best;
    }
}
```

### 術語表

- **Sliding Window（滑動視窗）**：兩個同方向移動的指標圈出一段連續區間，一邊擴大一邊視需要縮小。
- **Subarray（子陣列）**：陣列裡連續的一段，不能跳著挑。
- **Window size（視窗大小）**：視窗涵蓋的元素個數，可固定或隨條件變化。
- **Invariant（視窗條件／不變量）**：視窗必須一直維持成立的規則，被破壞就要縮小視窗。
