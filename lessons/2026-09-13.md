## 迭代與遞迴：兩種重複的形式、呼叫堆疊與尾遞迴 · 第 2 步

### 什麼是遞迴（Recursion）

昨天教的迭代（iteration）是用 for/while 迴圈重複執行，重複次數一開始就設定好。遞迴不一樣：函式在自己裡面呼叫自己本身，把一個大問題拆成一個更小的同樣問題，一路拆下去，直到問題小到可以直接回答為止。就像俄羅斯娃娃，一層一層打開，直到打開最小那層看到底。

### 遞迴的三個要素

以求和 1+2+...+n 為例：
1. **終止條件**：n 等於 1 時不再往下呼叫，直接回傳 1。
2. **遞迴呼叫**：n 還不是 1 時，呼叫 recur(n-1)，帶入更小的參數。
3. **返回結果**：每一層把 n 加上下一層傳回來的結果，往上一層送回去。

少了終止條件，函式會無窮無盡地呼叫自己，直到呼叫堆疊塞滿，丟出 `StackOverflowError`（堆疊溢位）。

```java
int recur(int n) {
    // 終止條件：n 為 1 時直接回傳
    if (n == 1) {
        return 1;
    }
    // 遞迴呼叫：呼叫自己並代入更小的 n - 1
    int res = recur(n - 1);
    // 返回結果：把這層算出的值送回上一層
    return n + res;
}
```

### 這東西用在哪

- **對工程師**：問題「長得跟自己的縮小版一樣」時就該想到遞迴（走訪資料夾樹、二元樹、巢狀 JSON），可以省下手動維護堆疊的麻煩；但要小心終止條件與呼叫深度，否則會堆疊溢位。
- **對產品端**：檔案總管的資料夾展開、留言串的巢狀回覆、組織架構的上下屬查詢，背後常常是遞迴實作。巢狀層數沒有上限時，理論上可能讓後端當掉或變慢——可以問工程師「巢狀深度有沒有上限」。

### 練習：LeetCode 509. Fibonacci Number（Easy）

[https://leetcode.com/problems/fibonacci-number/](https://leetcode.com/problems/fibonacci-number/)

F(0)=0、F(1)=1，之後每一項是前兩項相加：F(n)=F(n-1)+F(n-2)，求第 n 項。

- 終止條件：n < 2 時直接回傳 n。
- 遞迴呼叫：否則呼叫 fib(n-1) 和 fib(n-2)。
- 返回結果：把兩次呼叫的結果加總送回上一層。

複雜度：時間 O(2^n)（每層呼叫都分裂成兩個呼叫，呼叫次數指數成長）；空間 O(n)（呼叫堆疊最深疊到 n 層）。

```java
class Solution {
    public int fib(int n) {
        // 終止條件：n 是 0 或 1 就回傳 n
        if (n < 2) {
            return n;
        }
        // 遞迴呼叫並把兩層的結果加總
        return fib(n - 1) + fib(n - 2);
    }
}
```

### 今日術語表

| 術語 | 中文 | 定義 |
|---|---|---|
| Recursion | 遞迴 | 函式呼叫自己本身，把問題拆成更小的同樣問題。 |
| Base case | 終止條件 | 決定什麼時候不再往下呼叫、開始把結果往回送的條件。 |
| Recursive call | 遞迴呼叫 | 函式在自己內部呼叫自己，通常帶入更小的參數。 |
| Call stack | 呼叫堆疊 | 記錄「誰呼叫了誰、要回到哪裡」的記憶體空間，每多一層呼叫就多疊一份。 |
| Stack overflow | 堆疊溢位 | 呼叫堆疊疊太多層、超出系統上限，導致程式當掉的錯誤。 |
