## HashMap / HashSet：O(1) 查找的原理與代價 · 第 10 步

### Open Addressing: Another Way to Handle Collisions（開放定址法）

![雜湊衝突示例](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_map.assets/hash_collision.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

學號 12836 和 20336 後兩位都是 36，原文的雜湊函式只看後兩位，所以兩者算出同一個桶，兩個學號指向同一個姓名，這就是雜湊衝突。輸入空間（所有可能的 key）遠大於輸出空間（陣列索引），所以衝突理論上一定會發生。

**不串鏈子，改找下一格**：開放定址法不掛鏈結串列，所有資料直接放在陣列本身。桶被佔了就按固定規則找別的空桶。最簡單的規則是線性探查：從原桶一格一格往後看，到尾端繞回開頭。

**查找：走到空格才停**：從算出的桶開始逐格比對，對到就找到；碰到空格就能確定 key 不存在。只要空格夠多，平均仍是 O(1)。

**代價一：聚集**：被佔的格子連成長串，新資料撞進去要走到串尾，串又更長。所以負載因子要壓低，否則最壞退化成 O(n)。鏈結法即使負載因子超過 1 仍能運作，開放定址法格子用完就沒地方放。

**代價二：刪除要放墓碑**：不能把刪除的格子清成空，否則排在後面的資料會被誤判不存在。改放墓碑：查找時跳過繼續找，插入時可重用。

```
容量 8，桶號 = key % 8
放 10：桶2 空 → 放入
放 18：桶2 有人 → 桶3
放 26：桶2、3 有人 → 桶4
目前：[2]=10 [3]=18 [4]=26

刪 18，若直接清成空：
找 26：桶2 ≠ 26
  → 桶3 是空，停
  → 誤判沒有 26（錯！）

改放墓碑 X：
找 26：桶2 ≠ 26
  → 桶3 是 X，跳過
  → 桶4 = 26，找到
```

### 這東西用在哪

- 寫程式的人：Java 的 HashMap 用鏈結法，日常不會自己實作；但「衝突兩種解法」是面試常題，手寫雜湊表（LeetCode 705、706）多走此路。資料在連續陣列內，省節點物件、對 CPU 快取友善。Python dict、Java ThreadLocalMap 屬於此類。用錯的後果：刪除沒放墓碑導致查不到，或表太滿導致探查很長。
- 產品端：帳號重複檢查、登入狀態查詢、快取等「輸入一個值立刻回答有沒有」的功能，背後多半是雜湊表。不是資料量大就慢，而是用掉比例逼近上限才明顯變慢；系統在快滿前會擴容，擴容瞬間要搬家，可能偶爾短暫卡頓。可問工程師：這個查找表用到幾成滿會擴容？

### 動手寫 · LeetCode

[#705 Design HashSet](https://leetcode.com/problems/design-hashset/)（Easy）

**題目**：不准用內建 HashSet，自己實作 add、remove、contains。key 為 0 到 10^6 的整數，最多 10^4 次呼叫。

**解法步驟**：

1. 開大小 32768 的 int 陣列，-1 代表空格、-2 代表墓碑。
2. idx 函式乘大常數打散後取高 15 位當桶號。
3. find：從桶號往後探查，對到 key 回傳位置，碰到空格回傳 -1。
4. add：先 find，已存在就結束；否則往後找第一個空格或墓碑放入。
5. remove：找到後放墓碑。
6. contains：find 的結果不是 -1。

**複雜度**：時間平均 O(1)（操作數最多 10^4，只佔 32768 格的三成以下，探查只走幾步），最壞 O(n)；空間 O(m)，m 是固定的陣列大小。總操作數少於容量，連墓碑也不會填滿，find 一定會碰到空格而結束。

```java
class MyHashSet {
    static final int CAP = 1 << 15;
    static final int MASK = CAP - 1;
    static final int EMPTY = -1;
    static final int DEL = -2;
    int[] t = new int[CAP];

    public MyHashSet() {
        Arrays.fill(t, EMPTY);
    }

    // 乘大常數打散，取高 15 位當桶號
    private int idx(int key) {
        return (key * 0x9E3779B1) >>> 17;
    }

    // 回傳 key 所在格，找不到回傳 -1
    private int find(int key) {
        int i = idx(key);
        // 碰到空格才停，墓碑要跳過
        while (t[i] != EMPTY) {
            if (t[i] == key) return i;
            i = (i + 1) & MASK;
        }
        return -1;
    }

    public void add(int key) {
        if (find(key) >= 0) return;
        int i = idx(key);
        // 空格或墓碑都能放（>= 0 才是有人）
        while (t[i] >= 0) {
            i = (i + 1) & MASK;
        }
        t[i] = key;
    }

    public void remove(int key) {
        int i = find(key);
        // 放墓碑，不能清成空
        if (i >= 0) t[i] = DEL;
    }

    public boolean contains(int key) {
        return find(key) >= 0;
    }
}
```

### 今日術語表

| 術語 | 中文 | 定義 |
| --- | --- | --- |
| Open Addressing | 開放定址法 | 資料全放在陣列本身，桶被佔了就按規則找別的空桶 |
| Linear Probing | 線性探查 | 從原桶一格一格往後找，到尾端繞回開頭 |
| Probe | 探查 | 查找或插入時看一格有沒有人的動作 |
| Clustering | 聚集 | 被佔格子連成長串，新資料要走更遠 |
| Tombstone | 墓碑 | 刪除後留下的標記，查找跳過、插入可重用 |
| Hash Collision | 雜湊衝突 | 多個不同 key 算出同一個桶 |
