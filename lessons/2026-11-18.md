## 平衡樹 AVL · 第 7 步

### AVL Tree Recap: Keep the Tree Short

![AVL 樹的四種旋轉情況](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_tree/avl_tree.assets/avltree_rotation_cases.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

圖說：原文指出四種失衡情況分別對應右旋、先左旋後右旋、先右旋後左旋、左旋。右旋與左旋是一對鏡像，LR 與 RL 是另一對鏡像，認得兩組鏡像就等於記住一半。

**問題從哪來**：BST 的速度取決於樹高，插入、刪除後可能退化成鏈結串列，查詢從 O(log n) 變 O(n)。

**AVL 的解法**：要求每個節點平衡因子（左高減右高）落在 -1 到 1；失衡時用旋轉修復。旋轉只改幾個指標，O(1)，且中序順序不變，所以仍是合法 BST。

**整套流程**：插入或刪除後，遞迴回程每層先 updateHeight 再 rebalance；先看 node 平衡因子決定方向，再看 child 決定單旋或雙旋。整體 O(log n)。

**代價與取捨**：AVL 條件嚴格、查詢穩，但寫入要多維護高度與旋轉。Java 的 TreeMap 用紅黑樹，放寬條件換少旋轉。

**易錯點**：平衡因子比的是高度，不是節點個數。

### 這東西用在哪

- 寫程式：需要有序、範圍查詢、資料會增減時用 TreeMap／TreeSet；只要精確查找用 HashMap。
- 產品端：永遠按價格或時間排好、又能查範圍的功能多半是平衡樹或類似索引；一百萬筆約 20 層，沒平衡最壞要走一百萬步。

### LeetCode

[#110 Balanced Binary Tree](https://leetcode.com/problems/balanced-binary-tree/)（Easy）

題目：判斷二元樹是否每個節點左右子樹高度差都不超過 1。

解法步驟：

1. 寫 height 函式，空節點為 0，其餘為左右較高者加 1。
2. 左右高度差即平衡因子的絕對值。
3. 差值大於 1 回傳 -1 表示失衡。
4. 子樹回傳 -1 就直接往上傳。
5. 最外層檢查結果是否為 -1。

複雜度：時間 O(n)，每個節點只拜訪一次；空間 O(n)，遞迴深度等於樹高，最壞歪成一條線為 n，平衡時為 O(log n)。

```java
class Solution {
    public boolean isBalanced(
            TreeNode root) {
        return height(root) != -1;
    }

    // 回傳高度；不平衡回傳 -1
    private int height(TreeNode node) {
        // 空節點高度為 0
        if (node == null) return 0;
        int l = height(node.left);
        // 左子樹已失衡，直接往上傳
        if (l == -1) return -1;
        int r = height(node.right);
        if (r == -1) return -1;
        // 平衡因子的絕對值
        int diff = Math.abs(l - r);
        if (diff > 1) return -1;
        return Math.max(l, r) + 1;
    }
}
```

### 術語表

| 術語 | 定義 |
| --- | --- |
| AVL tree（AVL 樹） | 每個節點左右子樹高度差都不超過 1 的二元搜尋樹，靠旋轉維持。 |
| Balance factor（平衡因子） | 左子樹高度減右子樹高度，AVL 要求落在 -1 到 1。 |
| Rotation（旋轉） | 只改幾個指標就把子樹轉個方向，不改變中序順序。 |
| Rebalance（重新平衡） | 判斷該用四種旋轉中的哪一種並修好失衡節點的流程。 |
| Red-black tree（紅黑樹） | 另一種平衡樹，平衡條件較寬鬆、寫入旋轉較少，Java 的 TreeMap 用它。 |
