## Stack 堆疊：後進先出、括號配對與單調堆疊 · 第 2 步

### Array-based Stack：為什麼 push / pop 是 O(1)

陣列實作堆疊時，把陣列尾端當作堆疊頂：push 是在尾端新增元素，pop 是在尾端刪除元素，兩者都不需要搬動其他資料，時間複雜度都是 O(1)。

![基於陣列實現堆疊的入堆疊出堆疊操作](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_stack_and_queue/stack.assets/array_stack_step1.png)
圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

**為什麼一定要選尾端**：如果堆疊頂放在陣列開頭，push/pop 都要搬移其餘所有資料，退化成 O(n)；放在尾端則完全不用搬動。

**均攤下來還是 O(1)**：陣列滿了會「擴容」（resizing），單次搬遷是 O(n)，但因為擴容次數少，攤到每次 push 上平均仍是 O(1)（均攤時間複雜度，amortized time complexity）。

**另一種做法：鏈結串列**：把串列的頭節點當堆疊頂，push/pop 一樣是 O(1)；差別在陣列版記憶體連續、讀取較快，鏈結串列版不用擔心容量、但每個節點多一份指標開銷。這也是 Java 官方建議用 ArrayDeque 的原因之一。

⚠ 最容易搞錯的地方：手刻堆疊時把「陣列開頭」當堆疊頂，push/pop 會退化成 O(n)——一定要用尾端。

```java
class ArrayStack {
  private int[] data;
  private int top = -1;

  ArrayStack(int capacity) {
    data = new int[capacity];
  }

  void push(int val) {
    data[++top] = val; // 只動尾端，O(1)
  }

  int pop() {
    return data[top--]; // 只動尾端，O(1)
  }
}
```

### 這東西用在哪

- 對寫程式的人：需要頻繁「後進先出」操作時優先選陣列版的 ArrayDeque，記憶體連續、CPU 快取命中率高；自己手刻時若不慎把堆疊頂放在開頭，效能會從 O(1) 掉到 O(n)。
- 對產品端的人：undo/redo、瀏覽器上一頁這類「只從最新一筆處理」的功能，背後常是這種堆疊；就算歷史紀錄疊到上萬筆，push/pop 速度也不會變慢。

### 動手寫：LeetCode #155 Min Stack（Medium）

[題目連結](https://leetcode.com/problems/min-stack/)

設計一個堆疊，除了 push/pop/top，還要能在 O(1) 拿到目前最小值（getMin）。解法：用一個「輔助堆疊」同步記錄「目前為止的最小值」，push 時比較後決定輔助堆疊要 push 新值還是重複舊最小值，pop 時兩個堆疊一起 pop。

時間 O(1)：每個方法都只動兩個堆疊的尾端。
空間 O(n)：兩個堆疊各自最多存 n 筆資料。

```java
class MinStack {
  private Deque<Integer> stack = new ArrayDeque<>();
  private Deque<Integer> minStack = new ArrayDeque<>();

  public void push(int val) {
    stack.push(val);
    if (minStack.isEmpty() || val <= minStack.peek()) {
      minStack.push(val);
    } else {
      minStack.push(minStack.peek());
    }
  }

  public void pop() {
    stack.pop();
    minStack.pop();
  }

  public int top() {
    return stack.peek();
  }

  public int getMin() {
    return minStack.peek();
  }
}
```

### 今日術語表

- **Array 陣列**：資料連續排列的容器，可用 index 直接存取。
- **Resizing 擴容**：陣列裝滿時申請更大陣列並搬移資料。
- **Amortized time complexity 均攤時間複雜度**：少數貴操作平均攤到大量便宜操作上的複雜度。
- **Linked list 鏈結串列**：由節點與指標組成，不需連續記憶體。
- **Auxiliary stack 輔助堆疊**：額外的堆疊，用來輔助記錄某種資訊。
