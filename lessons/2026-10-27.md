## 雜湊衝突：鏈結法 chaining 與開放定址 open addressing · 第 1 步

### Hash Collision & Separate Chaining

![鏈式位址雜湊表](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_collision.assets/hash_table_chaining.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

**概念**

- 雜湊表依 key 算出桶號（bucket，陣列的一格），把鍵值對放進去。原始雜湊表每個桶只能放一個鍵值對，兩個 key 算出同一桶就是雜湊衝突（hash collision）。
- 衝突必然發生：key 近乎無限、桶有限，即抽屜原理（pigeonhole principle）。
- 笨辦法是一衝突就擴容，簡單有效但要搬大量資料、重算雜湊值，效率太低。兩個改良方向：改良結構讓衝突時也能運作；只在衝突嚴重時才擴容。結構改良分鏈式位址與開放定址，今天只學前者。
- 鏈式位址（separate chaining）：把每個桶改成一條鏈結串列，鍵值對是節點，衝突的鍵值對都存在同一條串列。
- 插入：算桶號 → 走訪串列，key 已存在就更新，否則接上新節點。查詢：算桶號 → 沿串列比對 key。刪除：把節點從串列拆掉。
- 節點必須存 key，因為同桶的資料桶號都相同，只能靠比對 key 分辨。
- 複雜度：算桶號 O(1)，再走一條鏈；鏈短時平均接近 O(1)，全擠同一桶時是 O(n)。Java 8 起 HashMap 的鏈長到 8 且桶數夠多時會轉成紅黑樹，最壞降為 O(log n)。

**這東西用在哪**

- 寫程式：Java 的 HashMap／HashSet 就是鏈式位址；hashCode() 要分散、equals() 要正確，否則退化成 O(n)。
- 產品端：帳號重複檢查、名單去重、快取等功能背後多半是雜湊表，資料量放大時通常仍很快，前提是桶數隨資料增加且資料分布平均；故意製造衝突可造成 hash flooding 攻擊。

**LeetCode：[#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）**

自己實作 put／get／remove，不可用內建 HashMap。做法：769 格桶陣列，key % 769 算桶號，每桶一條鏈結串列。時間：平均 O(1)（桶數固定，嚴格來說鏈長隨 n 成長），最壞 O(n)；空間 O(n + 769)。

```java
class MyHashMap {
    // 串列節點：存一組 key-value
    private static class Node {
        int key, val;
        Node next;
        Node(int k, int v) {
            key = k;
            val = v;
        }
    }

    private static final int SIZE = 769;
    private Node[] buckets =
        new Node[SIZE];

    // 算出 key 該去哪個桶
    private int idx(int key) {
        return key % SIZE;
    }

    public void put(int key,
                    int value) {
        int i = idx(key);
        Node n = buckets[i];
        // 沿著鏈找，已存在就更新
        while (n != null) {
            if (n.key == key) {
                n.val = value;
                return;
            }
            n = n.next;
        }
        // 沒找到：新節點接在鏈頭
        Node nd = new Node(key, value);
        nd.next = buckets[i];
        buckets[i] = nd;
    }

    public int get(int key) {
        Node n = buckets[idx(key)];
        while (n != null) {
            if (n.key == key) {
                return n.val;
            }
            n = n.next;
        }
        // 整條鏈都沒有
        return -1;
    }

    public void remove(int key) {
        int i = idx(key);
        Node cur = buckets[i];
        Node prev = null;
        while (cur != null) {
            if (cur.key == key) {
                Node nx = cur.next;
                // 刪的是鏈頭：桶改指向下一個
                if (prev == null) {
                    buckets[i] = nx;
                } else {
                    prev.next = nx;
                }
                return;
            }
            prev = cur;
            cur = cur.next;
        }
    }
}
```

**術語表**

| 術語 | 中文 | 定義 |
|---|---|---|
| Hash collision | 雜湊衝突 | 兩個不同 key 算出同一個桶號 |
| Bucket | 桶 | 雜湊表陣列裡的一格 |
| Key-value pair | 鍵值對 | 一筆 key 配 value 的資料 |
| Separate chaining | 鏈式位址 | 每個桶是一條鏈結串列，衝突的資料排同一條 |
| Linked list | 鏈結串列 | 節點記住下一個節點、串成一條的結構 |
| Open addressing | 開放定址 | 撞到就去找別的空桶，下一步教 |
| Pigeonhole principle | 抽屜原理 | 東西比抽屜多，必有抽屜放兩個以上 |
