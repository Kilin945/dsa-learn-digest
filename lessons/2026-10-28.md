## 雜湊衝突：鏈結法 chaining 與開放定址 open addressing · 第 2 步

### Open Addressing & Linear Probing

鏈式位址是在桶外面掛鏈結串列；開放定址（open addressing）則不加額外結構，所有鍵值對都直接放在陣列的桶裡，衝突時改找別的桶。最簡單的做法是線性探查（linear probing）：從算出的桶開始一次往後一格，找到第一個空桶就放，走到尾端繞回開頭。

![開放定址（線性探查）雜湊表的鍵值對分佈](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_collision.assets/hash_table_linear_probing.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

圖中的雜湊函式讓最後兩位相同的 key 對映到同一個桶，透過線性探查，它們依次被存在該桶以及之下的桶中。

![在開放定址中刪除元素導致的查詢問題](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_hashing/hash_collision.assets/hash_table_open_addressing_deletion.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

直接刪除元素會留下空桶；查詢走到空桶就會停止，空桶之下的元素因此被誤判為不存在。

- **插入**：算桶，被佔用就往後走，遇到空桶放入。
- **查詢**：同樣往後走，找到 key 就回傳 value；遇到空桶代表不在表裡。
- **聚集**：連續被佔用的區段越長，越容易再被撞到，區段越滾越長，增刪查改變慢。需控制載入因子並適時擴容。
- **刪除**：不能清成空桶，要改標墓碑（tombstone）。查詢遇墓碑繼續走，插入可重複利用墓碑。

```java
// 線性探查查詢
int find(int key) {
  int i = key % cap;
  // 遇到空桶才停
  while (st[i] != EMPTY) {
    if (st[i] == USED
        && keys[i] == key) {
      return i;
    }
    // 往下一格，到尾巴繞回開頭
    i = (i + 1) % cap;
  }
  return -1;
}
```

### 這東西用在哪

- 寫程式：資料連續放在陣列、省記憶體、對 CPU 快取友善；ThreadLocalMap 使用線性探查，Java HashMap 使用鏈式位址。載入率太高或直接清空桶刪除都會出問題。
- 產品端：依編號查資料、去重、快取多半是雜湊表。填得不滿時一百筆與一萬筆一樣快，快滿時急速變慢，所以會在約一半到七成滿時擴容，擴容時的搬家會造成偶爾卡頓。可問工程師：用多滿、何時擴容、擴容會不會卡。

### LeetCode · [#706 Design HashMap](https://leetcode.com/problems/design-hashmap/)（Easy）

自己實作 put、get（沒有回傳 -1）、remove，key 範圍 0 到 10^6，操作最多 10^4 次。

1. 三個陣列：keys、vals、狀態（0 空、1 使用中、2 墓碑），桶數取質數 20011。
2. 起點桶為 key % 20011。
3. put：往後走到空桶；相同 key 就更新；優先使用第一個墓碑。
4. get：遇空桶回傳 -1，跳過墓碑。
5. remove：找到後標墓碑。

時間 O(1) 平均（載入率低於一半，探查很短；最壞 O(n)）；空間 O(N)（陣列大小固定）。

```java
class MyHashMap {
  static final int N = 20011;
  int[] k = new int[N];
  int[] v = new int[N];
  // 0=空桶 1=使用中 2=墓碑
  byte[] s = new byte[N];

  public void put(int key, int value) {
    int i = key % N;
    int tomb = -1;
    while (s[i] != 0) {
      if (s[i] == 1 && k[i] == key) {
        // key 已存在，直接更新
        v[i] = value;
        return;
      }
      // 記下第一個墓碑
      if (s[i] == 2 && tomb < 0) {
        tomb = i;
      }
      i = (i + 1) % N;
    }
    // 有墓碑就優先重複利用
    int p = tomb >= 0 ? tomb : i;
    k[p] = key;
    v[p] = value;
    s[p] = 1;
  }

  public int get(int key) {
    int i = key % N;
    // 遇到空桶才代表找不到
    while (s[i] != 0) {
      if (s[i] == 1 && k[i] == key) {
        return v[i];
      }
      i = (i + 1) % N;
    }
    return -1;
  }

  public void remove(int key) {
    int i = key % N;
    while (s[i] != 0) {
      if (s[i] == 1 && k[i] == key) {
        // 標墓碑，不清成空桶
        s[i] = 2;
        return;
      }
      i = (i + 1) % N;
    }
  }
}
```

### 術語表

| 術語 | 定義 |
|---|---|
| Open addressing 開放定址 | 衝突時在陣列內另找空桶存放，不外掛串列 |
| Linear probing 線性探查 | 從衝突的桶開始一次往後一格找空桶 |
| Bucket 桶 | 雜湊表陣列裡的一個格子 |
| Clustering 聚集 | 連續被佔用的桶越長越容易再被撞到 |
| Tombstone 墓碑 | 刪除後留下的「已刪除」標記 |
| Load factor 載入因子 | 已用桶數 ÷ 總桶數 |
