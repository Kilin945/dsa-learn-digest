## HashMap / HashSet：O(1) 查找的原理與代價 · 第 8 步

### LinkedHashMap & TreeMap: When Order Matters

**HashMap 不保證順序**：key 經雜湊函式落入某個桶，位置與放入先後無關，所以走訪（iterate）HashMap 拿到的是桶的順序；擴容 rehash 後順序還可能改變。

**LinkedHashMap：多串一條線**：它是 HashMap 加一條雙向鏈結串列。查找仍走雜湊表，get/put 平均 O(1)，走訪沿串列，得到插入順序；開啟存取順序模式時，每次讀寫都把該筆移到尾端，最久沒用的在最前面。代價是每筆多兩個指標。

**TreeMap：真的排序，但慢一級**：底層紅黑樹，key 永遠排序，支援最小、最大、區間查詢；key 必須可比較，get/put 為 O(log n)。

| 結構 | 走訪順序 | get / put |
|---|---|---|
| HashMap | 不保證 | 平均 O(1) |
| LinkedHashMap | 插入序／存取序 | 平均 O(1) |
| TreeMap | 依 key 排序 | O(log n) |

⚠ 小整數 key 的 HashMap 走訪常剛好由小到大，只是巧合（Integer 的雜湊值就是自己），不能依賴。

```java
Map<String, Integer> a =
    new HashMap<>();
Map<String, Integer> b =
    new LinkedHashMap<>();
Map<String, Integer> c =
    new TreeMap<>();
// 依序 put c、a、b 後走訪：
// HashMap：順序不保證
// LinkedHashMap：c, a, b
// TreeMap：a, b, c
```

### 這東西用在哪

**對寫程式的人**：只問有沒有、幾次用 HashMap；要保留放入順序用 LinkedHashMap／LinkedHashSet；要最小最大、區間用 TreeMap／TreeSet；LRU 快取用存取順序的 LinkedHashMap。拿 HashMap 假設有序，上線資料一多順序就變；拿 TreeMap 當一般查表則多付 O(log n)，key 不可比較還會丟 ClassCastException。

**對產品端的人**：「最近瀏覽 10 筆」「購物車保持加入順序」「快取滿了踢最久沒用的」背後多半是帶順序的雜湊結構；「依價格排序」「查 100~500 元區間」「排行榜」多半是樹狀排序結構。雜湊型查找不管多大都近乎瞬間；排序型 100 萬筆約 20 步；真正會垮的是快取沒設上限，記憶體被吃光。可以問工程師：「這個快取有上限嗎？滿了怎麼淘汰？」

### 動手寫 · LeetCode

[#146 LRU Cache](https://leetcode.com/problems/lru-cache/)（Medium）

**題目在說什麼**：設計容量固定的快取。get(key) 回傳值，沒有回 -1，並視為剛用過；put(key, value) 寫入或更新，超過容量就踢掉最久沒被用過的那筆。get 與 put 都要 O(1)。

**怎麼用今天學的東西解**：
1. 繼承 LinkedHashMap，第三個參數傳 true 開啟存取順序模式，每次讀寫都把該筆移到尾端。
2. get 用 getOrDefault(key, -1)，找到時自動移到尾端。
3. put 直接呼叫 super.put，新增或更新同樣算用過。
4. 覆寫 removeEldestEntry，回傳 size() > cap，就會踢掉最前面（最久沒用）的那筆。

**複雜度**：時間 O(1)，查找走雜湊表平均 O(1)，移到尾端只是改幾個指標；空間 O(capacity)，超過容量就踢掉，最多存 capacity 筆。

```java
import java.util.*;

class LRUCache extends
    LinkedHashMap<Integer, Integer> {
    private final int cap;

    public LRUCache(int capacity) {
        // true 代表依存取順序排列
        super(capacity, 0.75f, true);
        cap = capacity;
    }

    public int get(int key) {
        // 找不到回 -1，找到會移到尾端
        return super.getOrDefault(
            key, -1);
    }

    public void put(
        int key, int value) {
        super.put(key, value);
    }

    @Override
    protected boolean
        removeEldestEntry(
        Map.Entry<Integer, Integer> e) {
        // 超過容量就踢掉最久沒用的
        return size() > cap;
    }
}
```

### 今日術語表

- **iterate（走訪）**：把集合裡的元素依序一個個拿出來看。
- **LinkedHashMap（鏈結雜湊表）**：HashMap 外加一條雙向鏈結串列，記住插入或存取順序，get/put 仍平均 O(1)。
- **doubly linked list（雙向鏈結串列）**：每個節點同時記得前一個和後一個是誰，能 O(1) 把節點搬到尾端。
- **access order（存取順序）**：依最近一次被讀或寫排序，剛用過的排最後。
- **TreeMap（樹狀映射）**：底層紅黑樹，key 永遠排序，支援最小最大與區間查詢，get/put 為 O(log n)。
- **cache（快取）**：把常用資料暫放在快速的地方，避免重複取得或計算。
- **LRU（最久未使用淘汰）**：快取滿了先踢掉最久沒被用到的那筆。
