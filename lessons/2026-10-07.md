## Queue 佇列與 Deque：先進先出、環形佇列與雙端佇列 · 第 4 步

### Linked-List Queue: Add at Tail, Remove at Head（用鏈結串列做佇列）

![基於鏈結串列實現佇列的入列出列操作](https://raw.githubusercontent.com/krahets/hello-algo/main/zh-hant/docs/chapter_stack_and_queue/queue.assets/linkedlist_queue_step1.png)

圖：[Hello 算法](https://www.hello-algo.com/) · CC BY-NC-SA 4.0

**圖怎麼看**：把鏈結串列（由節點串成的鏈，每個節點記著下一個節點是誰）的頭節點當作佇列首、尾節點當作佇列尾。規則是佇列尾僅可新增節點，佇列首僅可刪除節點：入列是在尾節點後接新節點，出列是拿掉頭節點，原本的第二個節點成為新的頭。

**為什麼鏈結串列也能當佇列**：佇列只要求一端新增、另一端刪除。鏈結串列不需連續空間，節點用參考指向下一個節點，新增或刪除只改幾個參考。

**front 與 rear**：front 指頭節點，rear 指尾節點。入列：舊 rear 的 next 指向新節點，rear 改指新節點。出列：front 改指下一個節點，舊頭由 GC 回收。兩者都是 O(1)，因為 rear 直接告訴我們尾巴在哪，不必從頭走一遍。

**與環形陣列比**：環形陣列要先定容量，滿了得換大陣列並搬資料；鏈結串列無容量問題，代價是每個節點多存一個參考、節點散落記憶體，讀取不如連續陣列順。兩者入列出列都是 O(1)，Java 實務預設仍推薦 ArrayDeque。

> ⚠ 方向不能反：必須尾進頭出。單向鏈結串列刪尾節點要先找到倒數第二個節點，只能從頭走，變成 O(n)。這也是雙端佇列要改用雙向鏈結串列的原因。

```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int val) {
        this.val = val;
    }
}

class LinkedListQueue {
    private ListNode front;
    private ListNode rear;
    private int size = 0;

    public void offer(int num) {
        ListNode n = new ListNode(num);
        // 空的：頭尾都是新節點
        if (front == null) {
            front = n;
            rear = n;
        } else {
            // 掛到尾端，rear 後移
            rear.next = n;
            rear = n;
        }
        size++;
    }

    public int poll() {
        int num = peek();
        // 頭節點往後一個，舊頭交給 GC
        front = front.next;
        size--;
        return num;
    }

    public int peek() {
        if (size == 0) {
            // 簡化：空佇列回 -1
            return -1;
        }
        return front.val;
    }
}
```

**一句話**：鏈結串列做佇列，頭節點出、尾節點進，靠 front 與 rear 讓入列出列都是 O(1)。

### 這東西用在哪

**對寫程式的人**：單機一般用途選 ArrayDeque（環形陣列，連續記憶體、不需每個元素配節點物件）。Java 的 LinkedList 雖實作 Queue，但每個元素是獨立節點物件，資料量到數十萬以上時記憶體與 GC 負擔明顯。JDK 的 ConcurrentLinkedQueue、LinkedBlockingQueue 是鏈結式佇列，懂 front/rear 才讀得懂它們的設計。不確定時選 ArrayDeque。

**對產品端的人**：叫號、訂單依序處理、批次寄通知、匯出報表等待清單，背後多半是佇列。佇列本身加減很快，排一百筆和一百萬筆單次速度差不多；會拖慢的是處理速度趕不上進來的速度。等待時間約等於隊伍長度除以每秒處理筆數。也要問清楚隊伍存在哪：只在記憶體的話，重啟後排隊資料會消失。

可直接問工程師：這個隊伍每秒處理幾筆、最壞排到多長、重啟後排隊的資料還在嗎？

### 動手寫 · LeetCode

[#933 Number of Recent Calls](https://leetcode.com/problems/number-of-recent-calls/)（Easy）

**題目在說什麼**：每次收到請求呼叫 ping(t)，t 為毫秒時間且嚴格遞增。回傳過去 3000 毫秒內（[t-3000, t]，含本次）的請求數。

**怎麼用今天學的東西解**：
1. 用 Queue 存每次 ping 的時間，t 遞增，所以隊首永遠最舊。
2. ping(t) 先 offer(t) 入列尾。
3. peek 隊首，若小於 t-3000 就 poll，重複到隊首在窗口內。
4. 回傳 size()。
5. Java 的 LinkedList 是雙向鏈結串列，offer 接尾、poll 取頭，就是今天的鏈結式佇列。

**複雜度**：
- 時間 O(1) 攤銷：每個請求只入列一次、出列一次。
- 空間 O(k)：只留窗口內請求，k 最多 3001。

```java
import java.util.*;

class RecentCounter {
    private Queue<Integer> q;

    public RecentCounter() {
        q = new LinkedList<>();
    }

    public int ping(int t) {
        // 新請求排到佇列尾
        q.offer(t);
        // 隊首太舊就出列
        while (q.peek() < t - 3000) {
            q.poll();
        }
        // 剩下的都在窗口內
        return q.size();
    }
}
```

### 今日術語表

- **Linked List 鏈結串列**：由節點串成的鏈，每個節點存資料並記著下一個節點是誰，不需連續記憶體。
- **Node 節點**：鏈結串列的一格，含資料與指向下一個節點的參考。
- **Reference 參考**：Java 裡指向物件的東西，可想成地址。
- **Head / Tail 頭節點／尾節點**：鏈的第一個與最後一個節點，做佇列時對應佇列首與佇列尾。
- **Singly Linked List 單向鏈結串列**：節點只記得下一個，刪尾要從頭走到倒數第二個。
- **GC 垃圾回收**：Java 自動清掉沒人指著的物件。
- **Amortized 攤銷**：把偶爾較貴的操作平均分攤到每次的平均成本。
