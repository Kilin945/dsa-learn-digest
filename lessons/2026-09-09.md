## 空間複雜度：記憶體也要算，遞迴呼叫堆疊的隱藏成本 · 第 3 步

### 今日概念：遞迴堆疊裡的平方階空間

昨天教了「遞迴深度為 n，就有 n 個堆疊幀同時存在，空間是 O(n)」，但這個結論有個前提：每一層堆疊幀裝的東西大小固定。如果遞迴函式在每一層裡自己又配置了一個容器（例如陣列），而且這個容器的大小會隨遞迴深度改變，堆疊空間就不能只看「疊了幾層」，還要看「每一層裡面裝了多少東西」，兩者要一起乘起來才是真正佔用的空間。

以下圖為例：遞迴深度為 n，每一層都建立一個陣列，長度分別是 n、n-1、…、2、1，平均長度約 n/2。把 n 層加總起來，大約是 n²/2 的量級，所以整體空間複雜度是 O(n²)，比單純「深度 n 就是 O(n) 堆疊」多疊了一個次方。

⚠ 最容易搞錯的地方：看到「遞迴深度是 n」就直接寫下空間複雜度是 O(n)，這只在每一層堆疊幀大小固定不變時才成立。只要每一層還額外配置了會隨深度變化大小的資料，就要把「疊了幾層」跟「每層佔多少空間」相乘，直接套「深度 = 空間」會低估真正的用量。

```java
// 遞迴時每層都配置一個陣列
void quadraticRecur(int n) {
    if (n <= 0) return;
    // 這層自己的暫存陣列
    // 長度是 n，隨層數遞減
    int[] nums = new int[n];
    quadraticRecur(n - 1);
}
```

### 這東西用在哪

**對寫程式的人**：遞迴函式若每一層都建立容器，要注意容量會不會隨層數變化（例如分治法合併步驟、遞迴逐層建構矩陣）。沒注意到的話，時間複雜度看起來還好，記憶體卻會比預期漲得快很多。

**對產品端的人**：如果工程師說某個遞迴或分批功能「資料量變大時記憶體漲得比想像快」，很可能就是這種情況——資料量從一百筆到兩百筆，記憶體不是漲兩倍，而是接近漲四倍（平方關係），可追問門檻值與有無分批替代方案。

### LeetCode 練習

[#118 Pascal's Triangle](https://leetcode.com/problems/pascals-triangle/)（Easy）：用遞迴由外往內建構每一列，每列陣列長度隨層數遞增（1、2、…、numRows），總空間跟今天教的規律一樣是 O(n²)，時間也是 O(n²)（建第 i 列花 O(i)，加總約 n²/2）。

```java
public List<List<Integer>> generate(int numRows) {
    List<List<Integer>> result = new ArrayList<>();
    buildRow(numRows, result);
    return result;
}

private void buildRow(int numRows, List<List<Integer>> result) {
    if (numRows == 0) return;
    // 先把前面所有列都蓋好
    buildRow(numRows - 1, result);
    int r = result.size();
    List<Integer> row = new ArrayList<>();
    // 這一列的陣列長度是 r + 1
    for (int i = 0; i <= r; i++) {
        if (i == 0 || i == r) {
            row.add(1);
        } else {
            List<Integer> prev = result.get(r - 1);
            row.add(prev.get(i - 1) + prev.get(i));
        }
    }
    result.add(row);
}
```

### 今日術語表

- **Stack frame 堆疊幀**：每次呼叫函式時，系統在呼叫堆疊頂端建立的一塊空間，存放參數、區域變數、返回位址等，函式 return 後釋放。
- **Recursion depth 遞迴深度**：遞迴呼叫自己的層數，也就是同時有多少個還沒 return 的堆疊幀。
- **Quadratic space 平方階空間複雜度**：佔用空間與 n 的平方成正比，常見於矩陣、圖，或每層遞迴各自配置長度遞減陣列的情況。
