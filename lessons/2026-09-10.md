## 空間複雜度：記憶體也要算，遞迴呼叫堆疊的隱藏成本 · 第 4 步

### 今日概念：Exponential Space Complexity（指數階空間複雜度）

昨天教的 O(n)、O(n²) 看的都是「同一時間堆疊上有幾層還沒 return」。今天這一步不同：如果一個遞迴函式每呼叫一次自己，就再分裂成兩個子呼叫（例如建立一棵滿二元樹），整個呼叫關係展開後會長成一棵樹，這棵樹的節點總數才是空間複雜度真正在算的東西。

層數為 n 的滿二元樹，節點數量是 2^n − 1 個：第一層 1 個（2^0）、第二層 2 個（2^1）、第三層 4 個（2^2）……一路加總約等於 2^n。這是多項式成長（如昨天的 n²）跟指數成長的差別：n 從 10 變 20，n² 只變 4 倍，2^n 卻變成 1024 倍。

**⚠ 最容易搞錯的地方**：呼叫堆疊的深度（O(n)，因為系統只沿著一條路徑往下走、往上 return）跟整個過程建立的節點總數（O(2^n)）是兩件不同的事，兩者都要算進空間複雜度，不能只看堆疊深度。

```java
// 假設 TreeNode 有 left/right
// 建立深度為 n 的滿二元樹
TreeNode buildTree(int n) {
    if (n == 0) {
        return null;
    }
    TreeNode root = new TreeNode(0);
    // 每次呼叫都分裂成兩個子呼叫
    root.left = buildTree(n - 1);
    root.right = buildTree(n - 1);
    return root;
}
```

### 這東西用在哪

- 對寫程式的人：看到函式裡呼叫自己兩次以上，就要警覺可能是指數階，n 超過三十左右就可能跑不完，需要剪枝、記憶化或動態規劃。
- 對產品端的人：「窮舉所有排列組合」這種功能，選項數量一旦從二三十個加到四五十個，回應時間可能暴增到跑不完，要先問清楚規模上限。

### LeetCode #78 Subsets（Medium）

[https://leetcode.com/problems/subsets/](https://leetcode.com/problems/subsets/) —— 給不含重複數字的陣列，列出所有子集。用「每個元素選或不選」建模成二元遞迴樹，走到底記錄一條路徑，n 個元素共 2^n 條路徑／子集。時間 O(n·2^n)、空間 O(n·2^n)（主要是輸出空間，遞迴堆疊本身只有 O(n)）。

```java
List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    dfs(nums, 0, new ArrayList<>(), res);
    return res;
}

void dfs(int[] nums, int i, List<Integer> path, List<List<Integer>> res) {
    if (i == nums.length) {
        res.add(new ArrayList<>(path));
        return;
    }
    dfs(nums, i + 1, path, res);        // 不選 nums[i]
    path.add(nums[i]);
    dfs(nums, i + 1, path, res);        // 選 nums[i]
    path.remove(path.size() - 1);
}
```

### 術語表

- Exponential（指數階）：成長速度依 2^n 增加，n 每加 1 數量就翻倍。
- Full binary tree（滿二元樹）：除最底層外，每個節點都恰好有兩個子節點的二元樹。
- Recursion tree（遞迴樹）：把每次遞迴呼叫畫成節點展開後的樹狀圖。
- Backtracking（回溯法）：先選擇往下遞迴，回來後撤銷再試下一個選擇。
- Stack depth（堆疊深度）：呼叫堆疊上同時存在、還沒 return 的堆疊幀數量。
