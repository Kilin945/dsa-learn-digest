這週學了兩塊主題：字串（String）的不可變性與 StringBuilder， 以及 Linked List（鏈結串列）的基本結構與指標技巧。 下面是幾題回想題，順序從簡單到深入，兩位都可以先自己想過一遍再往下看解答—— 不需要查資料，光靠讀過的每日信就答得出來。

🧠 回想題

  1. Java 的 String（字串物件）建立後為什麼說它「不可變（immutable，意思是內容一旦建立就不能被改動）」？ 當你寫 s = s.concat("test")，這一行實際上發生了什麼事？
  2. 如果要在一個迴圈裡把很多小字串組成一個很長的字串，為什麼建議用 StringBuilder（一種專門用來拼接字串、內部可重複使用同一塊記憶體的工具類別）而不是一直用 + 號接？ 如果硬用 + 號接，執行到後面會發生什麼現象？
  3. （接續上題，偏程式細節）StringBuilder.append() 為什麼說它是「平攤 O(1)（amortized O(1)，意思是雖然偶爾會比較慢，但平均下來每次操作的成本是常數）」？ 如果迴圈跑了 n 次 append()，整體的時間複雜度是多少？
  4. 承上題，如果同一個迴圈改成用 String 的 + 號接 n 次，總複雜度會變成多少？為什麼會跟 StringBuilder 差這麼多？
  5. Linked List（鏈結串列，一種用「引用」把一堆節點串起來，而不像陣列佔用連續記憶體的結構）為什麼不能像陣列一樣直接用 index（索引）跳到第 n 個元素？取第 n 個元素要花多少代價？
  6. 為什麼說在 Linked List 中插入一個新節點是 O(1)（也就是不管串列多長，代價都固定）？這個「O(1)」有一個前提，是什麼情況下才成立？如果不滿足這個前提，插入實際上要花多少？
  7. （偏程式細節）dummy head（假頭節點，一個不裝資料、擺在真正頭節點前面的節點）是為了解決什麼問題？如果沒有它，刪除或插入「第一個節點」要另外寫什麼特殊處理？寫完程式後，函式最後應該回傳 dummy 還是 dummy.next？
  8. （偏程式細節）快慢指標（fast-slow pointers，讓兩根指標從同一個起點出發，一根一次走兩步、一根一次走一步）用來找串列中點時，如果串列長度是偶數（例如 6 個節點），迴圈跑完後 slow 會停在第幾個節點？這跟迴圈條件寫成 fast != null && fast.next != null 有什麼關係？

—— 解答 ——

  1. String 物件一旦建立，裡面存的字元內容就不會再被改動。concat()（以及任何看起來像「改字串」的方法）其實是拿目前的內容複製一份、加工後回傳一個全新的 String 物件；原本 s 指向的那個物件內容完全沒動，只是變數 s 改成指向新物件。
  2. 因為 StringBuilder 內部維護一塊「可以動態變大」的字元緩衝區，append() 平攤下來只要 O(1)，整個迴圈跑 n 次總共只要 O(n)。若用 + 號，每次串接都要把「目前為止已經有的全部內容」複製一份到新物件裡，跑到後面內容越長、每次複製越貴，執行速度會明顯變慢（越後面越明顯的卡頓）。
  3. StringBuilder 內部緩衝區滿了才需要「整批搬到更大的空間」，這種比較貴的操作次數很少，把它分攤到每一次 append() 上，平均每次還是常數時間，所以叫「平攤 O(1)」。n 次 append 總成本就是 O(n)。
  4. O(n²)。因為第 1 次接要複製長度 1 的內容、第 2 次要複製長度 2、…、第 n 次要複製長度 n，加總起來是 1+2+…+n，等於 n(n+1)/2，也就是 O(n²)——這就是為什麼迴圈裡不建議用 + 號接字串。
  5. 因為 Linked List 的節點是靠「引用」一個個串起來，不是連續記憶體，沒辦法像陣列一樣直接算出第 n 個元素的位置，只能從頭節點開始一步步往後走。取第 n 個元素要 O(n)。
  6. 因為插入新節點只需要改兩個引用（讓新節點指向後面的節點、再讓前面的節點指向新節點），不用像陣列一樣整批搬動資料。但前提是你已經「拿著指向目標位置的指標」；如果還得從頭節點開始找到那個位置，找的過程本身就要 O(n)，這時插入整體還是 O(n)。
  7. 一般規則是「刪除／插入某節點，要去改它前一個節點的引用」，但頭節點沒有前一個節點可改，所以第一個節點永遠要另外寫特殊處理。加上 dummy head 後，頭節點前面多了一個假節點，讓「處理第一個節點」也變成跟處理其他節點一樣的一般情況，不用再寫例外分支。函式最後要回傳 dummy.next（真正的頭節點），不是 dummy 本身（那只是輔助用的假節點）。
  8. 6 個節點時，slow 會停在第 4 個節點（偏後面那一個）。因為迴圈條件是「fast 還沒走到底，且 fast 的下一步也還沒走到底」才繼續走；fast 每次走兩步、slow 走一步，fast 走到第 6 個節點（走到底）時迴圈就停了，此時 slow 剛好走了 3 步、停在第 4 個節點。如果節點數是奇數，中點就唯一，沒有這個「取前一個還是後一個」的問題。
