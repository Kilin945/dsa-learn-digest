這週我們學了什麼？這週圍繞同一條主線：樹（一種像家族圖的資料結構，每個節點最多有兩個孩子，叫「二元樹」）。從「怎麼把樹上的每個節點走過一遍」，到「把資料排好放進樹裡找得快」（二元搜尋樹，簡稱 BST），再到「樹歪了怎麼扶正」（AVL 樹與旋轉）。

先不要往下看解答，試著在心裡或紙上回答每一題，再對答案。想不出來也沒關係，卡住的地方就是最值得複習的地方。

✍️ 回想題

Q1（概念與應用）「走訪」就是把樹上每個節點都拜訪一次。DFS（深度優先：一條路走到底再回頭）和 BFS（廣度優先：一層一層往下走，要用「佇列」，也就是先進先出的排隊隊伍）各適合什麼情境？請各舉一個：「我想知道每一層有哪些節點」和「我想算整棵子樹的某個結果」，分別該用哪一種？

Q2（概念與應用）二元搜尋樹（BST）規定的大小關係是什麼？有人說「只要每個節點比它的左孩子大、比右孩子小就是 BST」，這句話哪裡不夠嚴謹？

Q3（概念與應用）你手上有一批資料，想「由小到大」輸出，又不想另外做排序。如果把它們放進 BST，要用哪種走訪方式？為什麼這樣就剛好是排好的？

Q4（概念與應用）小明把 1、2、3、4、5、6、7 依這個順序一個一個插入一棵空的 BST。這棵樹會長成什麼樣子？之後查詢一個數字會發生什麼事？用在資料量一百萬筆的系統上，會有什麼後果？

Q5（概念與應用）AVL 樹是一種「會自己維持平衡」的 BST。它用什麼規則判斷一個節點「太歪了」？它犧牲了什麼、換來了什麼？（提示：想想插入時多做的事，以及查詢的速度保證。）

Q6（實作與複雜度）遞迴版 DFS 和迭代版 DFS（自己準備一個堆疊，也就是「後進先出」的容器）都是時間 O(n)。迭代版在「前序」走訪時，為什麼要先推右孩子、再推左孩子？另外，遞迴版在什麼情況下會出事、出什麼事？

Q7（實作與複雜度）刪除 BST 中一個「有兩個孩子」的節點時，要用誰來頂替它？這個替身怎麼找？BST 的插入／刪除成本為什麼寫成 O(h) 而不是 O(log n)？h 是什麼？

Q8（實作與複雜度）某節點 node 左邊太重，要做右旋。令 child = node.left，grand_child = child.right。請寫出右旋要改的三個指標（用 Java 或偽碼皆可），並回答：整個操作的時間複雜度是多少？旋轉前後的中序走訪結果會變嗎？

—— 解答 ——

A1要「每一層」的資訊 → 用 BFS（例如逐層列印、找最短層數）；要「整棵子樹」的結果（例如算子樹高度、總和）→ 用 DFS。兩者走完整棵樹都是 O(n)，差別在於「走的順序」符不符合你的問題形狀。

A2規定是「整串左子樹的所有節點 < 根 < 整串右子樹的所有節點」，不是只跟父子比。只比父子的話，可能出現「右孩子的左孩子」比祖先還小的情況，這樣就不是合法 BST，查詢會找錯方向。

A3用中序走訪（左 → 根 → 右）。因為左邊整串都比根小、右邊整串都比根大，先走完左、再訪問根、最後走右，輸出自然是升序。成本 O(n)，不用額外排序。

A4每次新數字都比現有的都大，所以都掛在最右邊，樹會變成一條斜斜的「鏈」，長得像鏈結串列。查詢要從頭一個個比，變成 O(n)。資料一百萬筆時，每次查詢最壞要走約一百萬步，而不是約 20 步，系統會明顯變慢。

A5規則是「平衡因子」（左子樹高度 − 右子樹高度）必須落在 −1 到 1 之間，超出就是失衡，要用旋轉修復。代價是插入／刪除時要多做檢查與旋轉；換來的是樹高永遠維持在 O(log n)，查詢、插入、刪除都有穩定的 O(log n) 保證，不會被插入順序拖垮。

A6堆疊是後進先出，右孩子先推入、左孩子後推入，下一個彈出的就是左孩子，所以會先走左邊，路線跟遞迴一模一樣（根 → 左 → 右）。遞迴版背後用「呼叫堆疊」記著每一層；樹很深（例如退化成一條鏈）時，呼叫堆疊會爆掉，丟出 StackOverflowError。迭代版把堆疊放在堆積記憶體（heap）自己管，可以避開這個問題。空間都是 O(h)。

A7用「右子樹中最小的節點」（也就是中序後繼，中序走訪的下一個）來頂替：先走到右孩子，再一路往左走到底就是它。這個替身比左邊全部都大、比右邊其他都小，BST 規則仍成立。成本是 O(h)，h 是樹高（從根到最深葉子的層數）；樹平衡時 h ≈ log n，退化時 h = n，所以不能直接寫成 O(log n)。

A8三個指標：
① child.right = node;（node 降為 child 的右孩子）
② node.left = grand_child;（grand_child 改掛到 node 左邊）
③ 把原本指向 node 的那條線（父節點的指標，或樹根）改指向 child。
只動固定幾個指標，時間 O(1)。中序走訪順序不會變（grand_child 仍然夾在 child 與 node 之間），所以旋轉後仍是合法的 BST。

🌱 這週的主線：走訪 → 有序 → 會退化 → 用旋轉救回來。下週繼續加油！
