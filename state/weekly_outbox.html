這週從「陣列」走到「空間複雜度」與「遞迴堆疊」。下面 7 題把整週串起來，故意混著出——不管是工程師還是產品端同事，都先自己想過一遍再看解答。標了 (工程師限定) 的題目需要一點程式碼細節，產品端同事可以跳過那幾題，其他題目兩位都答得出來。

1. ArrayList（Java 內建的「可變長陣列」，可以隨插入自動變大的清單）明明底層還是普通陣列，為什麼加東西進去平均起來還是很快？「resize」（陣列滿了之後重新配置一塊更大空間、把舊資料整個搬過去）明明是 O(n) 的操作，怎麼會說平均每次 add() 只要 O(1)？
2. 如果你已經知道資料量固定、裡面存的都是數字，為什麼工程師常常寧可選 int[]（存純數值的陣列）也不用 ArrayList<Integer>？用 ArrayList 存數字，會在「記憶體連續」這件事上吃虧在哪裡？
3. 「空間複雜度」到底在算什麼東西的空間？為什麼「輸入的資料」不算進去，但「輸出的結果」卻要算？
4.（工程師限定） LeetCode 26 這題，如果解法是「另外開一個新陣列來裝過濾後的結果」，空間複雜度是 O(n)；但用「雙指標」（two pointers，兩個各自移動、分工不同任務的索引）可以把它改寫成 O(1) 空間的「原地」（in-place，直接在原本的陣列裡面改，不額外開新容器）解法。這兩個指標大致上是怎麼分工的？
5. 一個迴圈跑 n 次、跟一個遞迴函式（自己呼叫自己的函式）呼叫自己 n 層，兩者的「時間」都可能是 O(n)，但「空間」的表現卻不一樣。為什麼遞迴會多佔空間，迴圈卻不會？（提示：想想什麼是「呼叫堆疊」——每次呼叫還沒 return 就會先疊在上面等著。）
6.（工程師限定） 如果一個遞迴函式，第 n 層額外配置了一個長度 n 的陣列，第 n-1 層配置長度 n-1 的陣列……一路到第 1 層配置長度 1 的陣列，為什麼整體空間複雜度會變成 O(n²)，而不是原本遞迴堆疊本身的 O(n)？
7.（工程師限定） 比較三種遞迴：(a) 每次呼叫只把問題規模減 1 的線性遞迴；(b) 每次呼叫都讓問題規模砍半的「分治」（divide and conquer，把問題拆成小塊分別處理再合併）遞迴；(c) 每次呼叫都分裂成兩個子呼叫（例如建一棵滿二元樹）。三者的「呼叫堆疊深度」各是多少？為什麼 (c) 的堆疊深度明明只有 O(n)，但整個呼叫展開後建出來的節點總數卻是指數成長的 O(2ⁿ)？這兩件事為什麼不衝突？
—— 解答 ——

1. 因為 ArrayList 每次「搬家」都不是搬到剛好大 1 格的新陣列，而是搬到「兩倍大」的新陣列。容量每次翻倍，代表要搬家的次數很少（只有 log n 次），而且離上次搬家越久，下次搬家前累積的免費 add() 次數就越多——把這些搬家的成本平均分攤到每一次 add() 上，平均下來每次只要 O(1)，這就叫「攤還」（amortized，把偶爾一次貴的操作成本分攤到很多次操作上算平均）。

2. ArrayList 存物件時，因為 Java 的「自動裝箱」（autoboxing，把基本型別的數值自動包成物件）機制，ArrayList<Integer> 裡面存的其實不是數字本身，而是一堆指向 Integer 物件的「參照」（reference，指向某塊記憶體位置的指標），這些 Integer 物件本身散落在記憶體各處、不連續。相較之下 int[] 裡的數字是真的一個接一個連續排列。連續記憶體對 CPU 快取比較友善，散落的物件則容易「快取未命中」（cache miss，CPU 要找的資料不在快取裡，得多花時間去別的地方拿），所以多了一層跳轉、速度較慢。已知大小又追求效能時，優先選 int[]。

3. 空間複雜度算的是「暫存空間」（algorithm 執行過程中額外用掉、跟輸入大小有關的空間，例如另外開的陣列、遞迴堆疊）加上「輸出空間」，但不含「輸入空間」（因為輸入本來就已經存在那裡了，不是這個演算法額外花的成本）。實務上輸出通常很小甚至可以忽略，所以大家講空間複雜度時常常只提暫存空間，但這不代表輸出不算，只是通常不是重點。

4. 一個指標（可以想成「慢指標」）負責記錄「目前結果應該寫到哪一格」；另一個指標（「快指標」）負責一格一格往前掃描整個陣列。快指標每掃到一個「該留下」的元素，就把它寫到慢指標的位置，然後慢指標才往前移一格；不該留下的元素快指標直接跳過、慢指標不動。掃完之後，慢指標之前的區段就是結果，全程只用原本的陣列，沒有另外開新容器，所以是 O(1) 空間。

5. 迴圈每跑完一輪就結束了，不會有東西留在記憶體裡等著；但遞迴函式每呼叫自己一次，就會在「呼叫堆疊」（call stack，記錄目前有哪些函式呼叫還沒執行完、等著 return 的一疊資料）上多疊一個「堆疊幀」（stack frame，一次函式呼叫需要記住的區域變數、返回位置等資訊），而且要等到最深那一層先 return，上面的才能一層層跟著結束。深度為 n 的遞迴，堆疊上同時存在 n 個還沒結束的呼叫，所以佔用 O(n) 空間；迴圈沒有這種「疊著等」的結構，用完就釋放，是 O(1)。

6. 呼叫堆疊本身確實只有 n 層，是 O(n)；但這題多了「每一層還各自佔用一塊隨深度變化的空間」。第 n 層佔 n、第 n-1 層佔 n-1……一路加到第 1 層佔 1，總和是 n + (n-1) + (n-2) + … + 1，這是一個等差數列求和，結果約等於 n²/2，去掉常數之後就是 O(n²)。重點是：堆疊「深度」（有幾層）跟每一層「各自佔多少空間」是兩件事，要把每層的空間都加總起來，才是真正的總空間複雜度。

7. (a) 線性遞迴每次只減 1，要減 n 次才會到底，堆疊深度是 O(n)。(b) 分治遞迴每次讓問題規模砍半，砍 log n 次就會到底（因為 n 反覆除以 2，除到剩 1 大約要除 log n 次），堆疊深度是 O(log n)。(c) 每次分裂成兩個子呼叫時，「深度」看的是從最上層走到最底層要經過幾層——因為每一層問題規模只是簡單減 1（例如樹的高度一層層往下），所以深度仍然是 O(n)；但因為每一層都分裂成兩支，「總共呼叫了幾次、建了幾個節點」是把每一層的呼叫數翻倍再翻倍地乘起來，這是指數成長，加總後是 O(2ⁿ)。深度是「從根走到葉最長要幾步」，節點總數是「這棵樹總共有幾個點」——一個看的是路徑長度，一個看的是整體規模，兩者本來就是不同的度量方式，所以不衝突。
