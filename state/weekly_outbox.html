這週的主題：HashMap / HashSet

這週都在學「雜湊表（Hash Table）」：一種把資料依照它的「編號」直接放進對應格子，讓你不用一個一個翻找的結構。Java 裡的 HashMap（存「鍵→值」配對的表）與 HashSet（只存「鍵」、用來問「有沒有」的集合）就是它的實作。下面的題目請先自己想，再往下看解答。小提醒：「O(1)」意思是不管資料多少，花的時間大致固定；「O(n)」是資料越多、時間等比例變長；「O(log n)」是資料變很多時，時間只慢慢增加一點。

🧠 回想題

Q1（概念與應用）　你要做一個功能：「使用者輸入手機號碼，立刻告訴他這個號碼註冊過了沒」，註冊名單有一百萬筆。你會選 HashSet 還是「把名單放進清單、一個一個比對」？為什麼？

Q2（概念與應用）　所謂「雜湊衝突」是什麼意思？如果衝突特別嚴重（大量資料全撞進同一格），HashMap 的查找速度會發生什麼事？

Q3（概念與應用）　HashMap 裡裝的資料越來越多，Java 會在「裝到某個比例」時自動把格子數量加倍並重新安排所有資料（稱為 rehash，重新計算每筆資料該放哪格）。這個比例叫什麼、預設是多少？如果你事先就知道要放大約十萬筆，有什麼做法可以減少這個麻煩？

Q4（概念與應用）　你想統計一篇文章裡每個單字出現幾次，該用 HashMap 還是 HashSet？key 和 value 各放什麼？

Q5（概念與應用）　你做了一個「客戶」物件當 HashMap 的 key，放進去之後，有人把客戶的「身分證字號」欄位改掉了（這個欄位參與雜湊計算）。接下來用這個客戶去查，會發生什麼事？為什麼？

Q6（概念與應用）　三種需求各該選哪一種 Map？(a) 只要查得快、順序不重要　(b) 要照「放進去的順序」或「最近用過的順序」走訪，例如做快取　(c) 要照 key 由小到大排序，或查「某個範圍內的資料」。（選項：HashMap、LinkedHashMap、TreeMap）

Q7（實作與複雜度）　Java 8 之後，同一格裡的串列太長會變成「紅黑樹」（一種會自動保持平衡的樹狀結構）。請問：(1) 樹化的兩個條件是什麼？(2) 最壞情況的時間從什麼變成什麼？(3) 為什麼說「樹化只是保底」，不能靠它取代好的 hashCode？

Q8（實作與複雜度）　看這段程式，寫出輸出結果，並說明時間與空間複雜度（用 n 代表陣列長度、k 代表不同元素種類數）：
int[] a = {3, 1, 3, 2, 1, 3};
Map<Integer,Integer> m = new HashMap<>();
for (int x : a) m.merge(x, 1, Integer::sum);
System.out.println(m.get(3) + " " + m.get(2));

—— 解答 ——

A1　選 HashSet。它平均 O(1)，一百萬筆也幾乎是瞬間回答；清單逐筆比對是 O(n)，最壞要翻一百萬次，使用者變多就會越來越慢。

A2　衝突＝兩個不同的 key 算出同一個格子（桶）。Java 用「鏈結法」，把撞在一起的資料串成一串。查找成本是 O(1＋鏈長)：分散得好平均 O(1)；全撞在同一格，最壞退化成 O(n)，像在清單裡慢慢找。找到格子後還要用 equals 確認是不是同一個 key。

A3　叫「負載因子」（元素數 ÷ 格子數），Java 預設 0.75，超過就容量加倍並 rehash。單次擴容是 O(n)，但平均分攤到每次 put 仍是 O(1)（稱「攤銷」）。已知約十萬筆時，建立 HashMap 時就預留足夠容量（例如 new HashMap<>(150000)，讓十萬 ÷ 容量不超過 0.75），就能避免反覆擴容。

A4　用 HashMap：key 放單字、value 放出現次數。HashSet 只能回答「有沒有」，記不了次數。這就是「頻率表」，掃一輪即可，時間 O(n)、空間 O(k)。

A5　很可能查不到。hashCode 決定放哪一格，欄位改了之後 hashCode 變了，查找會去「新的格子」找，但資料還躺在「舊的格子」。所以 key 放進去後，不能再改會影響雜湊值的欄位。（合約：equals 相等則 hashCode 必須相等。）

A6　(a) HashMap；(b) LinkedHashMap（多一條雙向串列記錄順序，仍平均 O(1)，可做 LRU 快取，即「淘汰最久沒用的」）；(c) TreeMap（紅黑樹，O(log n)，可排序、可查區間）。HashMap 的走訪順序依格子順序，不保證。

A7　(1) 同一格的鏈長達 8，且總格子數至少 64。(2) 最壞從 O(n) 降為 O(log n)。(3) 樹化要求 key 可比較才有效，而且它只是救急；若 hashCode 本身分散不好，大量資料仍擠在少數格子，整體還是慢，所以好的 hashCode 才是根本。

A8　輸出 3 1（3 出現 3 次、2 出現 1 次）。掃一輪 n 個元素、每次 merge 平均 O(1)，時間 O(n)；表中只存 k 種元素，空間 O(k)。
