這週學了兩個主題：AVL 平衡樹（11/14～11/18）和樹的經典題型（11/19～11/20，深度與直徑）。下面 7 題先自己想一想，不要偷看信末的解答。前 4 題不用寫程式，只憑讀過的內容就答得出來；後 3 題要碰到程式細節和複雜度。

名詞小提醒：節點 = 樹上的一個點；樹高 = 從根往下最長的那條路有幾層；O(log n) = 資料變 2 倍，步驟只多一步，很快；O(n) = 資料變 2 倍，步驟也跟著變 2 倍。

Part 1 · 概念與應用題（不用寫程式）

Q1. 二元搜尋樹（BST）是「左邊的值都比自己小、右邊的值都比自己大」的樹，查找時每次可以排除一半的資料。如果有人把 1、2、3、4、5…… 依序一個一個放進普通 BST，樹會變成什麼形狀？查找速度會從多快變成多慢？這就是為什麼需要 AVL。

Q2. AVL 用平衡因子（= 左子樹高度 減 右子樹高度）來監控樹有沒有歪掉。請問平衡因子允許的範圍是多少？某個節點的平衡因子變成 2 或 −2 時，代表什麼意思、AVL 會做什麼事？

Q3. 旋轉是「只調整少數幾條連接線，就把偏重的一邊拉回來」的動作。請問旋轉修好樹之後，節點由小到大的排列順序（中序）會不會被弄亂？這個特性為什麼重要？另外，旋轉本身要花多少時間？

Q4. 假設你是產品端，要在「訂單編號」資料上做大量的查找，同時資料會不斷新增、刪除。什麼情況下你會選 AVL 這類平衡樹，而不是普通 BST？選了 AVL 要付出什麼代價？

Part 2 · 實作與複雜度題

Q5. 某個節點 node 左邊太重（平衡因子 > 1），但它的左子節點 child 是右邊比較重。只做一次右旋能修好嗎？應該用哪一種旋轉組合？再說說：如果 child 的平衡因子剛好是 0（刪除時可能發生），要用單旋還是雙旋？

Q6. 寫出「樹的最大深度」的遞迴公式（空樹回傳多少？）。再追蹤這棵樹：根是 1，左子節點 2、右子節點 3，節點 2 底下再接一個左子節點 4，節點 4 底下再接一個左子節點 5。最大深度是多少？時間複雜度與遞迴堆疊的空間複雜度各是多少？（提示：空間跟樹高 h 有關。）

Q7. 「樹的直徑」是樹上任兩個節點之間最長路徑的邊數。承接 Q6 的那棵樹，直徑是多少？另外，為什麼不能只算「經過根節點」的那一條路，而要在每個節點都算一次「左深度 + 右深度」再取最大值？遞迴函式回傳的值和用來更新答案的值，各是什麼？

—— 解答 ——

A1. 每個新值都比前面大，全部掛在右邊，樹變成一條斜斜的長鏈（像鏈結串列）。查找從 O(log n) 退化成 O(n)，等於一個一個從頭找。

A2. 範圍是 −1 到 1。出現 2 或 −2 就是「某一邊太重、失衡」，AVL 會用旋轉（右旋、左旋、LR、RL 四種之一）把它修回來。

A3. 不會亂。中序順序不變，所以旋轉後仍然是合法的 BST，查找規則還能用。旋轉只改幾個指標，是 O(1)。

A4. 資料量大、查找很頻繁、又會持續新增刪除，而且擔心資料依序進來造成退化時，選 AVL，因為它保證最壞情況也是 O(log n)。代價是每次新增、刪除後要多做更新高度與旋轉的維護工作，程式也更複雜。

A5. 不能，只右旋修不好。要用 LR：先對 child 左旋，再對 node 右旋。child 平衡因子為 0 時，用單旋就能修好（刪除時的特殊情況）。

A6. depth(node) = 1 + max(depth(左), depth(右))，空樹為 0。這棵樹最長的路是 1→2→4→5，最大深度 = 4。時間 O(n)（每個節點只造訪一次），空間 O(h)（遞迴堆疊最深等於樹高）。

A7. 直徑 = 3 條邊（路徑 5→4→2→1→3 是 4 條邊？請注意：節點 5 到節點 3 為 5→4→2→1→3，共 4 條邊）。逐點計算：節點 1 的左深度 = 3（2→4→5 這條鏈）、右深度 = 1，總和 4，所以直徑 = 4。需要每個節點都算的原因是最長路徑不一定經過根；只看根會漏掉藏在某個子樹裡的更長路徑。遞迴回傳的是「單邊深度」（1 + max(左, 右)，給上一層用），用來更新全域答案的是「左深度 + 右深度」。時間 O(n)、空間 O(h)。
