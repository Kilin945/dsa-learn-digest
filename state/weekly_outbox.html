這週從 Big-O 的基本觀念一路走到 Array 的記憶體結構，中間串了 Two Sum 當主線案例。以下 8 題混合本週各天主題，由淺入深，先自己想過一輪再往下看解答。

🧠 回想題

Q1. 陣列 arr[5] 的存取是 O(1) 還是 O(n)？為什麼跟資料量無關？

Q2. 用單層迴圈找陣列最大值，這是哪個複雜度等級？操作次數跟 n 是什麼關係？

Q3. Two Sum 的暴力解（兩層迴圈找兩數之和）是 O(n²)，這個 n² 是怎麼跑出來的？

Q4. 把 Two Sum 優化成 HashMap 邊掃邊記的版本後，時間複雜度變成什麼？付出的代價（tradeoff）是什麼？

Q5. 如果一段程式先跑一個 O(n) 迴圈，接著跑一個 O(n²) 的巢狀迴圈，整體複雜度是多少？用到哪一條化簡規則？

Q6. Binary Search 為什麼是 O(log n)？它有什麼前提條件才能用？

Q7. 在陣列中間插入一筆資料是 O(n)，但接在陣列最後面插入卻是 O(1)，這兩者差在哪裡？

Q8（綜合）. 把 O(n²)、O(1)、O(log n)、O(n log n)、O(n) 由快到慢排序。接著：如果要在陣列「最前面」逐一插入 1000 筆資料，總複雜度會是多少？

—— 解答 ——

A1. O(1)。因為陣列是連續記憶體（contiguous memory），可以用「起始位址 + index × 每格大小」直接算出位置，不用一格格找，跟 n 大小無關。

A2. O(n)，線性時間（linear time）。掃過整個陣列一次，操作次數跟 n 成正比。

A3. 外層迴圈跑 n 次，內層迴圈每次都要掃完剩下的整個 n，兩層相乘變成 n × n = n²，這就是巢狀迴圈時間要相乘的化簡規則。

A4. O(n) 時間。代價是多花 O(n) 空間去存已經看過的數字（用 HashMap），這就是 Time-Space Tradeoff：用空間換時間。

A5. 整體是 O(n²)。循序執行的部分要相加：O(n) + O(n²)，但化簡時只留成長最快的主導項（dominant term），低階的 O(n) 直接丟掉。

A6. 因為每次都能把搜尋範圍對半砍掉，操作次數約等於 log₂(n)。前提是資料必須先排序好（sorted），否則沒辦法判斷該往哪一半找。

A7. 插在中間之後，後面所有元素都要往後搬移（shifting）才能維持連續記憶體的排列，所以是 O(n)；插在最後面如果還有空間，不需要搬動任何東西，直接放上去就是 O(1)。這就是陣列「隨機存取快」的代價。

A8. 排序：O(1) < O(log n) < O(n) < O(n log n) < O(n²)。在最前面逐一插入 1000 筆，每次插入都要搬移當時已有的所有元素，等於是 1000 次 O(n) 等級的操作相加，整體是 O(n²)（n 這裡代表最終陣列的大小）。
