這週我們從堆疊收尾，花了五天學佇列與雙端佇列，今天剛開始雜湊表。下面 7 題請先自己想，想完再看信末的解答。前 4 題是概念與應用題，不用寫程式；後 3 題是實作與複雜度題。

名詞小提醒：O(1) 的意思是「步數不會隨資料變多而變多」；O(n) 是「資料變多少倍，步數就大約多少倍」。

Q1（概念） 堆疊（Stack）是「後進先出」：最後放進去的東西最先拿出來。請各舉一個生活或軟體中的例子，說明「後進先出」和「先進先出」（佇列 Queue，先排隊的先處理）分別適合什麼情境。

Q2（概念） 客服系統有一堆客人在等回覆，規定「先來的先處理」。你會選堆疊還是佇列？如果選錯了，客人會遇到什麼問題？

Q3（概念） 雙端佇列（Deque）是頭、尾兩端都能新增與刪除的佇列。它和一般佇列比，多了什麼能力？請想一個「只用一般佇列做不到、或很彆扭」的情境。另外，Java 實務上我們這週一再建議用哪一個類別來實作佇列與雙端佇列？

Q4（概念） 雜湊表（HashMap）號稱「查找平均 O(1)」。用你自己的話說：為什麼它不用一個一個比對就找得到資料？另外，「平均」這兩個字暗示了什麼前提？如果這個前提被破壞，查找會發生什麼事？

Q5（實作） 環形佇列（用陣列做的佇列，尾端滿了就繞回開頭）：假設容量 capacity = 5，目前 front = 3、size = 4。請問 rear（下一個要放入元素的位置）的 index 是多少？公式是什麼？再入列一個元素後，size 變成多少？此時佇列是空、是滿、還是都不是？

Q6（實作） 追蹤程式（Java，ArrayDeque<Integer> d = new ArrayDeque<>();）：
d.offerLast(1); d.offerLast(2); d.push(3); d.offerFirst(4); d.pollLast(); d.pollFirst();
執行完後，d.peekFirst() 會回傳什麼？
提示：push 加在頭部，offer 加在尾部。

Q7（實作） LeetCode 1 Two Sum：給一個整數陣列和目標值 target，找出兩個數加起來等於 target 的位置。(a) 不用 HashMap、用兩層迴圈的做法，時間複雜度是多少？(b) 改用 HashMap 一邊走訪一邊找「搭檔」（target − 目前的數），時間複雜度降成多少？它用什麼換來這個速度？

—— 解答 ——

A1 後進先出：瀏覽器的「上一頁」（最近開的頁面最先退回）、括號配對、復原（Undo）。先進先出：排隊買票、客服進線、列印工作排程。判斷方式：想「最近的先處理」用堆疊，想「公平、按順序」用佇列。

A2 選佇列。若用堆疊，最後來的客人會先被服務，先來的客人可能一直被插隊、等不到，這就違反「先來先處理」。

A3 多出「兩端都能進出」的能力。例如：想從尾端撤銷最後一筆、同時從前端處理最舊一筆；或「最近的優先、也保留排隊」的混合情境。一般佇列只能尾進頭出。Java 實務統一用 ArrayDeque，用 Queue 或 Deque 型別宣告來表達意圖。

A4 雜湊函式（把 key 算成一個數字的公式）先算出雜湊值，再對容量取模得到陣列的位置（桶），直接跳過去，不用逐一比對。「平均」的前提是衝突（不同 key 算到同一個桶）不多。若大量衝突，同一個桶裡的東西要一個個比，查找就會退化變慢，最糟接近 O(n)。

A5 rear = (front + size) % capacity = (3 + 4) % 5 = 2。入列後 size = 5，等於 capacity，所以是「滿」。（空是 size = 0。這就是用 size 區分空與滿的好處。）

A6 逐步：offerLast(1) → [1]；offerLast(2) → [1,2]；push(3) 加頭 → [3,1,2]；offerFirst(4) → [4,3,1,2]；pollLast() 拿掉 2 → [4,3,1]；pollFirst() 拿掉 4 → [3,1]。peekFirst() 回傳 3。

A7 (a) 兩層迴圈 O(n²)。(b) HashMap 做法 O(n)：只走訪一次，每次查「搭檔」平均 O(1)。代價是多用額外記憶體（空間 O(n)）存已看過的數，這是「用空間換時間」。
